A solid chip is an assignment naming this address. A dashed chip is inherited — from a subnet, a name, or default — and the API says which, so the UI never has to guess why a client is where it is. A client whose schedule window is shut still shows its policy, marked as not in force. That is the honest reading: the assignment exists, it is simply not deciding anything right now.

Start and end are set together or not at all. Saving replaces any assignment this address already had, in whichever policy held it — one address, one assignment.

What this page is not

Clients here are observed by traffic. There is no ARP table, no DHCP lease list, and no device inventory behind this — a machine that has never sent a query does not appear, and one that stops asking stays listed with an old last_seen rather than dropping off. Names are a label you set, not something discovered from the network. FastAdHunter does not do reverse lookups to fill them in. The 24 h counts come from the same rolling window as the Dashboard, so they will not agree with a longer range picked on the history pages.
