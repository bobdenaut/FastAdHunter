Counters are cumulative since process start. Consecutive failures is the live one — it resets on a success, so it says what is happening now, where the totals say what has happened ever. The failure-run histogram counts closed runs by length. Many short runs is ordinary packet loss; a few long ones is an endpoint that goes away and comes back, which is what earns a penalty.

Why this is not a traffic pie

A per-query "which upstream answered" share cannot be drawn here, and no attempt is made to fake one: the address is deliberately not carried per query. What a query does report is the answering endpoint index, and only when an upstream actually answered — a cache hit or a block carries no endpoint at all. So this page charts health, which is what the data actually supports: attempts, failures, and how the adaptive strategy is currently treating each endpoint.

What the states mean

HEALTHYAnswering normally. Preferred for new queries.
PENALIZEDFailed enough to be stepped back. Each round lengthens the penalty. Still queried when nothing else is available — being penalized is not being removed.
PROBINGUnder test after a penalty. Successful probes return it to healthy.

Under the fallback strategy these states do not apply — degraded there simply means every endpoint carries a non-zero consecutive-failure count. The page names the strategy in force so the reading is never ambiguous.
