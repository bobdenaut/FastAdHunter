# p2.5-04 — Transport Error-Kind Fidelity

## Implementation Summary

The three `map_err(io::Error::other)` sites on the DoT/DoH paths now route
through one private classifier, so a caller sees `ConnectionRefused`,
`NetworkUnreachable`, `HostUnreachable`, `ConnectionReset` and a TLS/certificate
rejection as distinct `io::ErrorKind`s instead of a uniform `Other`. Pool
behaviour is untouched — this changes what the errors *say*, not what
`forward()` does with them. The RCODE-is-not-a-failure invariant (S1-G1 gate 5)
is now pinned by test.

### Pinned-API verification (done before coding)

The plan was written against an assumed `ProtoError` surface. The versions
pinned in `Cargo.lock` are `hickory-proto 0.26.1`, `hickory-net 0.26.1`,
`rustls 0.23.42`, `tokio-rustls 0.26.4`, and they do not match that assumption:

| Plan assumption | Pinned reality |
| --- | --- |
| The three sites yield `ProtoError` | They yield `hickory_net::NetError`. `tls_exchange`, `HttpsClientStream::builder(..).exchange(..)` and `DnsHandle::send`'s response stream are all `Result<_, NetError>` |
| `ProtoError` can wrap an `io::Error` reachable via `source()` | `ProtoError` in 0.26.1 has **no** `Io` variant at all (`hickory-proto-0.26.1/src/error.rs`). The synthetic test the plan describes cannot be constructed |
| A `rustls::Error` is observable in the chain of a real DoT/DoH failure | It is not, and does not need to be. `NetError::RustlsError` exists but is **never constructed** anywhere in `hickory-net 0.26.1` (declaration is its only occurrence). A rejected certificate arrives as an `io::Error` because `tokio-rustls` already converts `rustls::Error` into `io::Error::new(ErrorKind::InvalidData, err)` (`tokio-rustls-0.26.4/src/common/mod.rs:115`) |

Two consequences shaped the implementation, both preserving the plan's
decisions rather than changing them:

1. **The classifier takes `NetError`, not `ProtoError`.** Same role, same
   privacy, same three call sites.
2. **`NetError::Io` is not reachable through `source()`.** The variant is
   `Io(Arc<io::Error>)` — an unnamed field with no `#[from]`/`#[source]`, so
   `thiserror` generates no `source()` for it. A pure source-chain walk (what
   the plan's "Pass-through kinds" row describes) would find nothing and every
   real failure would fall to `Other`. The classifier therefore reads the
   variant first, then walks the chain for the nested cases.

The plan's chosen TLS classification survives intact and, as it turns out, for
free: `tokio-rustls` already stamps `InvalidData` on a certificate rejection,
`hickory-net`'s `From<io::Error> for NetError` carries it into `NetError::Io`
unchanged, and the pass-through rule then donates it verbatim. The explicit
rustls branch remains as the documented fallback for a chain that carries a
typed `rustls::Error` with no io error beneath it.

The plan's synthetic-chain test was rebuilt as the smallest equivalent: feed
`NetError::from(io::Error::new(kind, ..))` directly to `transport_error` and
assert the kind survives. It verifies the same contract (kind pass-through with
no live unreachable route) using the type the pinned API actually produces.

### Changes

**`crates/fah-dns/src/upstream/encrypted.rs`**

| Element | Shape |
| --- | --- |
| `transport_error(err: NetError) -> io::Error` | `io::Error::new(transport_error_kind(&err), fah_common::error_chain(&err))` — kind classified, full chain text preserved as the message |
| `transport_error_kind(&NetError) -> io::ErrorKind` | `NetError::Io(e)` → `e.kind()` verbatim (no allowlist); `NetError::H2(e)` → `e.get_io()`'s kind when the h2 failure is io-backed; otherwise walk `source()`, first `io::Error` found donates its kind, a `rustls::Error` anywhere in the chain → `InvalidData`; fallback `Other` |
| Call sites | DoT connect (`tls_exchange`), DoH connect (`HttpsClientStream::exchange`), `send_once` — the three the plan enumerated, and the only three that existed |

Precedence is as specified: an io error in the chain wins over the TLS
classification, so a TLS stream's underlying `ConnectionReset` stays
`ConnectionReset`. The classifier never produces `TimedOut` — that kind is
still minted only by the two existing `timeout(..)` wrappers, which p2.5-03's
invalidation trigger depends on.

**Tests added / strengthened**

| Test | Location | What it pins |
| --- | --- | --- |
| `dot_connect_to_a_dead_port_reports_connection_refused` | `encrypted.rs` | Live DoT connect to a closed TCP port → `ConnectionRefused` |
| `dot_fails_closed_when_the_certificate_is_untrusted` (strengthened) | `encrypted.rs` | Live untrusted-certificate handshake → `InvalidData`, not just "is_err" |

| `transport_error_leaves_a_wire_decode_failure_opaque` | `encrypted.rs` | A `NetError` with neither io nor rustls in the chain stays `Other` — a malformed answer is not a path failure |
| `a_decoded_rcode_is_not_an_upstream_failure` | `upstream/mod.rs` | S1-G1 #5: `SERVFAIL`, `NXDOMAIN`, `REFUSED` each leave `failures` at 0, reset a seeded `consecutive_failures` of 7 to 0, and end the walk (secondary `attempts` stays 0) |

The timeout class is already pinned from the caller's side by p2.5-03's
`dot_timeout_on_a_fresh_connection_leaves_nothing_pooled` and
`dot_timeout_invalidates_the_pooled_connection_so_the_next_query_reconnects`,
both of which assert `err.kind() == TimedOut`; a fourth test asserting the same
kind through the same rig would be a duplicate, so none was added.

Test-side helpers were consolidated rather than added to: `dot_pool_from(
addresses, tls, timeout_ms)` is the single DoT pool builder (`dot_pool_of`
delegates to it), `udp_server_with(count, reply)` is the single UDP mock
(`answering_udp_server` and `rcode_udp_server` are one-line wrappers), plus a
new `closed_tcp_addr()`.

### Design decisions

- **No new error type, no enum.** `io::Error` kinds are the whole surface, per
  the plan's "Out of scope".
- **`InvalidData` is reserved** on these transports for a TLS/protocol-layer
  path failure. Nothing else on these paths produces it: hickory's wire-decode
  errors surface as `NetError::Msg`/`NetError::Proto` with neither an io source
  nor a rustls one, and fall to `Other`. This is the contract Stage 1's S1.4
  tier can cite.
- **Message format.** `error_chain` from `fah-common` renders the full chain
  into the `io::Error`'s message, replacing the previous typed-source wrapping.
  The `debug!` at `upstream/mod.rs:198` prints `%err`, so the text it logs is
  the same or fuller than before.

### Known limitations / deferred

1. **`NetError::Timeout` classifies as `Other`.** Three things produce it, not
   two: the 5 s `CONNECT_TIMEOUT` inside `connect_tls_stream`, the
   `DnsMultiplexer`'s own `mux_timeout`, and — via
   `impl From<io::Error> for NetError` (`hickory-net-0.26.1/src/error.rs:207`)
   — **any kernel `ETIMEDOUT`/`WSAETIMEDOUT`**, which that impl rewrites into
   `NetError::Timeout` before the classifier ever sees it. So the task's scope
   line "kernel kinds (… `TimedOut`) pass through" is not met on these
   transports, while the plan's "only the wrappers mint `TimedOut`" is. No
   observable behaviour changes: `attempt_timeout` (default 800 ms) fires long
   before any kernel TCP timeout, and both hickory-internal timeouts are
   shadowed the same way (`connect()` wraps at `attempt_timeout`, `send_once`
   wraps at `attempt_timeout` against a mux timeout of `2 * attempt_timeout`).
   Mapping `NetError::Timeout` → `TimedOut` is a Stage 1 decision, not this
   task's: it would widen p2.5-03's invalidation trigger.
2. **`ErrorKind::Other` is not a stable contract for callers to match on** — it
   is the residue, not a class. Stage 1's S1.4 tier should key off the specific
   kinds, never off `Other`.
3. **DoH exchange-time failures stay `Other`.** `hickory-net`'s h2 path
   stringifies every send/receive failure into `NetError::Msg`
   (`h2.rs:155, 293–340, 357–391`), destroying the type before it reaches the
   classifier. The `H2` arm recovers only the io-backed handshake failure
   (`h2.rs:263`). Recovering the rest would mean parsing message text; that is
   a hickory limitation, not one this task can close. DoT is unaffected — its
   exchange errors arrive as `NetError::Io`.
4. **The `H2` arm has no unit test.** `h2 0.4.15` exposes no public
   constructor for an io-backed `h2::Error` (`Error::from_io` is
   `pub(crate)`, and the `From` impls cover only `proto::Error`, `Reason`,
   `SendError`, `UserError`), so the arm cannot be exercised without a live
   DoH server that resets mid-handshake — a rig this crate does not have.
   `h2::Error::get_io` itself is public and stable in 0.4.15.
5. **`dot_connect_to_a_dead_port_reports_connection_refused` costs ~2 s on
   Windows.** Loopback SYN to a closed port is retried by the OS
   (`TcpMaxConnectRetransmissions=2`, ~1 s then ~2 s back-off) before it
   reports `WSAECONNREFUSED`; worst case ~3 s. The test's `timeout_ms` is
   10000 so a loaded dev box cannot flip the result to `TimedOut`; the test
   ends on refusal, so the larger ceiling costs no wall-clock. On Linux/musl
   the same connect refuses immediately.
6. **Windows-only evidence for the live tests.** `ConnectionRefused` and
   `InvalidData` were observed on Windows 11; the classification is
   kernel-kind pass-through and `tokio-rustls`'s own mapping, neither of which
   is platform-specific, but no Linux/RB5009 run backs this yet.

### Not done (out of scope, per the plan)

No consumption of the classes (selection, penalties, alarms — Stage 1); no
plain-UDP or `resolve_host` change; no public error type; no logging change.

## Findings

Reviewed against the working-tree diff (`git diff --stat`: encrypted.rs +91/-21,
mod.rs +57/-0) plus the pinned `hickory-net 0.26.1`, `h2 0.4.15`,
`tokio-rustls 0.26.4` sources. Focused suite re-run: 34 passed, 2 ignored.

### F1 — Major: DoH exchange-path kinds do not pass through (library erasure, undocumented)

- **Evidence (measured from source):** `hickory-net-0.26.1/src/h2.rs` wraps every
  exchange-time failure as `NetError::from(format!(..))` → `NetError::Msg`
  (lines 155, 293–340, 357–391), and the h2 handshake failure as
  `NetError::H2(Arc<h2::Error>)` (line 263). `H2` has no `#[source]`, so the
  classifier's chain walk never sees the `io::Error` an `h2::Error` may carry.
- **Impact:** a `ConnectionReset`/`BrokenPipe` on a live DoH stream is
  reported as `Other`, and an io-backed h2 handshake failure likewise. The
  Implementation Summary's "a TLS stream's underlying `ConnectionReset` stays
  `ConnectionReset`" holds for DoT only. Stage 1's S1.4 tier would treat a
  DoH path failure as the unclassified residue.
- **Partial fix available (inference):** add a `NetError::H2(e)` arm that
  returns `e.get_io().map(io::Error::kind)` (`h2::Error::get_io` is public in
  0.4.15) — covers the handshake case. The stringified exchange cases cannot be
  recovered without parsing text; that is a hickory limitation.
- **Disposition:** **FIXED.** `transport_error_kind` gained a `NetError::H2(e)`
  arm returning `e.get_io()`'s kind. No unit test: `h2 0.4.15` exposes no
  public constructor for an io-backed `h2::Error` (`from_io` is `pub(crate)`)
  — recorded as limitation 4. The `Msg`-stringified exchange cases are
  recorded as limitation 3.

### F2 — Minor: kernel `TimedOut` is erased, and limitation 1 misstates the cause

- **Evidence:** `impl From<io::Error> for NetError` (error.rs:207) rewrites
  any io error of kind `TimedOut` into `NetError::Timeout`, which the
  classifier maps to `Other`. So `NetError::Timeout` has three sources, not
  the two limitation 1 lists: `CONNECT_TIMEOUT`, mux timeout, **and** any
  kernel `ETIMEDOUT`/`WSAETIMEDOUT`.
- **Impact:** the task's scope line "kernel kinds (... `TimedOut`) pass
  through" is not met on these transports; the plan's "only the wrappers mint
  `TimedOut`" is met. In practice `attempt_timeout` (default 800 ms) fires
  long before any kernel TCP timeout, so no observable behaviour changes.
- **Disposition:** **FIXED (text).** Limitation 1 rewritten to name all three
  sources and the `From<io::Error>` rewrite that causes the erasure. Code
  question deferred to Stage 1: mapping `NetError::Timeout` → `TimedOut` would
  widen p2.5-03's invalidation trigger.

### F3 — Minor: `dot_connect_to_a_dead_port_reports_connection_refused` has thin headroom on Windows

- **Evidence (inference):** Windows retransmits a loopback SYN twice
  (`TcpMaxConnectRetransmissions=2`, 1 s then 2 s back-off) before
  `WSAECONNREFUSED`; observed ~2 s, worst case ~3 s. `timeout_ms` is 4000.
- **Impact:** on a loaded dev box the attempt can cross 4 s, at which point
  the kind becomes `TimedOut` and the test fails with no code change — a flaky
  gate.
- **Disposition:** **FIXED.** `timeout_ms` raised 4000 → 10000. Re-run wall
  clock unchanged (~2 s), as predicted.

### F4 — Nitpick: test-helper duplication

- `rcode_udp_server` copies `answering_udp_server` verbatim except the reply
  builder (mod.rs:419–447). One `udp_server_with(count, reply: impl Fn(&Message) -> Message)`
  would serve both (principle 4).
- `dot_pool_with` and `dot_pool_of` build the same `DnsUpstreamsConfig` shape
  twice (encrypted.rs:371–410).
- **Disposition:** **FIXED.** Both consolidations applied — see the fix
  verification table. The earlier "defer, test-only" call was wrong: principle
  4 does not carve out test code.

### F5 — Nitpick: typed source dropped from the returned `io::Error`

- `io::Error::new(kind, String)` replaces `io::Error::other(err)`, so
  `source()`/downcast on the returned error no longer reaches the `NetError`.
  No caller uses it today and the plan fixed "message text" as the contract.
- **Disposition:** accept as designed; note only so a future caller does not
  expect a typed chain.
