## Implementation Summary

A transient socket error no longer ends a DNS listener. Both loops retry with
bounded backoff, escalate to process exit only after 40 consecutive errors with
no successful receive between them, and `--healthcheck` now proves the DNS path
answers instead of only re-parsing the config.

**What landed**

| Unit | Change |
| --- | --- |
| U1 | `crates/fah-dns/src/backoff.rs` — `RetryPolicy` / `RetryDecision`, pure, no clock, no I/O; the caller sleeps |
| U2 | `udp::run` / `tcp::run` return `ListenerDied` instead of `()`; error arm retries, never returns while retries remain |
| U3 | `Server` owns an `mpsc(1)` fatal channel; `Server::fatal()` awaits a listener's death |
| U4 | `main::run` selects shutdown-signal vs `dns.fatal()`; a fatal listener logs at `error` and exits `ExitCode::FAILURE` |
| U5 | `--healthcheck` sends an opcode-`Status` query to the configured `dns.listen` address; wildcard binds (`::` / `0.0.0.0`) use a loopback fallback. The probe has a 2 s read timeout and reports `config` or `dns-probe` on failure |

**Design decisions (deviations from the plan are marked ⚠)**

- Backoff: 10 ms doubling to a 1 s cap; 40th consecutive error is fatal
  (≈ 33.3 s of backoff before escalation). No error-kind inspection — the
  threshold decides fatality, as specified.
- ⚠ `ListenerDied` is `pub`, not `pub(crate)`. `Server::fatal()` is public, so
  a `pub(crate)` return type trips `private_interfaces` under `-D warnings` and
  the binary could not read `last_error`. Exported as `fah_dns::ListenerDied`.
- ⚠ The fatal channel is created in `Server::bind`, not `Server::serve`.
  `fatal()` needs a receiver even before `serve` is called, and `Server` holding
  its own `Sender` is what makes "recv never returns `None`" true by
  construction rather than by comment.
- ⚠ `hickory-proto` moved from `[dev-dependencies]` to `[dependencies]` of
  `fastadhunter`. The probe runs before the Tokio runtime exists and cannot
  borrow `fah-dns`' encoder. Already linked via `fah-dns`, so no new code enters
  the graph.
- The probe accepts any reply ≥ 12 bytes whose header id matches. It never
  decodes the body: the pipeline answers a non-`Query` opcode with `NotImp`
  before rules, cache and upstreams, so a passing probe cannot be faked by
  upstream health and cannot be failed by an unhealthy upstream.
- Escalation is process-wide by design: a dead UDP listener exits the process
  and takes the healthy TCP listener with it. A dead process is visible and
  restartable; a dead task inside a green process is neither.

**Known limitations / deferred**

- No test induces a *real* kernel `recv_from`/`accept` error; the seam added for
  F1 (below) injects `io::Error`s at the same call site instead, which is what
  the loops branch on.
- Process exit only helps where something restarts the process. RouterOS has no
  auto-restart (owner's device, out of scope here) — until it does, the
  healthcheck is what makes a dead listener visible.
- Docker `HEALTHCHECK` unchanged, as specified.

## Decisions

| Decision | Value |
| --- | --- |
| Backoff | 10 ms initial, ×2 per consecutive error, capped at 1 s |
| Escalation | 40th consecutive error with no receive between them → `Fatal` |
| Error classification | none; the threshold decides fatality |
| Fatal signaling | `mpsc::channel::<ListenerDied>(1)` owned by `Server`, `try_send` on return |
| Probe | opcode `Status`, blocking `std::net::UdpSocket`, 2 s read timeout; probes the configured `dns.listen` address when concrete, with a loopback fallback for wildcard binds (`::` / `0.0.0.0`) |
| Exit codes | 0 all checks pass; 1 otherwise, naming `config` or `dns-probe` |

## Follow-ups / Deferred

- The dead-port test bounds the probe as `elapsed(dead port) − elapsed(config
  failure)`, not as absolute wall-clock. ⚠ The plan's absolute "exit 1 within
  3 s" failed at 3.58 s under a parallel `cargo test`: process start alone costs
  ~1.5 s there. The delta isolates the probe and keeps the 3 s bound meaningful.
- This loop shape is the template Phase 3 DoT/DoH and SNI listeners inherit.
- Listener death is still invisible to `/telemetry`; only the healthcheck and
  the exit code report it. A counter belongs with `p2.5-05` if wanted.

### Findings

**F1 · should-fix — acceptance criterion "induced transient error" untested**
`crates/fah-dns/src/udp.rs:27` / `crates/fah-dns/src/tcp.rs` (error arms)
Evidence: no test produces a real `recv_from`/`accept` `io::Error`; the
garbage-burst test is a *successful* recv of junk bytes, `backoff.rs` tests
only the policy math, the new fatal test only the healthy negative. The task
file requires the induced-error test; the plan's §Tests substituted weaker
coverage — the Sleep→continue wiring and Fatal→`ListenerDied`→exit chain are
unexercised end to end.
Remediation (owner decision, before `DONE`): add a seam (trait over
recv/accept, fake yielding N `Err` then `Ok`) and test both loops against it;
or explicitly accept the substitute coverage here as the criterion's
disposition. The Known-limitations note above already records the gap;
acceptance makes it a decision instead of an omission.

**F2 · should-fix — probe hard-codes `127.0.0.1`; a concrete bind false-fails**
`crates/fastadhunter/src/main.rs:178`
Evidence: `let target = SocketAddr::from((Ipv4Addr::LOCALHOST, port));`
`fah-config` accepts any parseable IP for `dns.listen.address` and the bind
uses exactly that address. Default `::` answers v4-mapped loopback (plan's
case), but a concrete `192.168.88.2` or `::1` bind serves clients while every
healthcheck times out 2 s and exits 1 — red-while-green, permanently. The
plan's rationale ("a v4 bind answers directly") is false for concrete binds;
the task file said "against the configured listen address". Found
independently by three reviewers; validator-confirmed.
Remediation: probe the configured `dns.listen.address` when it is concrete,
falling back to `127.0.0.1` only for `::`/`0.0.0.0`; or reject/document
non-loopback-answering binds. Current deployment (default bind) unaffected —
fix or defer is the owner's call.

**F3 · note — pending `dns.listen.port` change flips healthcheck red until restart**
`crates/fastadhunter/src/main.rs:159`
Evidence: the probe reads the port from the config file; `dns.listen` is a
boot key, so after `POST /api/v1/config` persists a new port
(`restart_required: true`) the listener keeps the boot port while every
healthcheck probes the pending one and exits 1 on a healthy resolver.
Remediation: none required in code now; name the pending-restart case in the
probe failure message, or note it wherever `restart_required` keys are
documented. Defer.

**F4 · note — `Server`'s doc comment now attaches to `ListenerDied`**
`crates/fah-dns/src/server.rs:26`
Evidence: `ListenerDied` was inserted between the pre-existing
`/// Owns the UDP + TCP listener tasks…` comment and `pub struct Server`;
rustdoc mis-documents `ListenerDied` and leaves `Server` undocumented.
Remediation (fix before `DONE`, one-line): move the `ListenerDied` struct
above the comment or below `impl Server` — comment edits are hook-forbidden,
relocation is the fix.

### Residual risks (informational)

- Exit-on-fatal is permanent on RouterOS (no auto-restart): netwatch then
  serves unfiltered DNS until manual restart; the `main.rs` fatal log's
  "so the process is restarted" reads as Docker-generic, not this deployment.
- Probe passes while rules/cache/upstreams are broken (by design) and TCP/53
  is unprobed (out of scope by plan).
- During a backoff sleep (≤ 1 s) no recv is posted; datagrams beyond
  `SO_RCVBUF` drop silently — inherent to sleep-and-continue.
- Simultaneous UDP+TCP fatal drops the second `ListenerDied` (harmless: the
  first already exits the process).
- Windows dev only: `WSAECONNRESET` recv noise counts as retry errors
  (warn + short sleep); traffic resets the counter, Linux unaffected.
- Suppressed low-confidence items: single-`recv_from` probe hardening
  (source/id re-read loop) — only relevant if the container isolation model
  changes.
