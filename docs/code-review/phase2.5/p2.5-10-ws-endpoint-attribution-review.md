# p2.5-10 — WS Endpoint Attribution

## Implementation Summary

The per-query `endpoint` p2.5-05 put on `QueryEvent` now reaches the WS
`query` message. Wiring only — the value, its semantics and its serde rule
were already in place; `fah-api`'s wire DTO simply never read it (p2.5-09 F1).

| File | Change |
| --- | --- |
| `crates/fah-api/src/wire.rs` | `QueryItemResponse.endpoint: Option<u8>`, `skip_serializing_if = "Option::is_none"`; `From<QueryRecord>` reads `event.endpoint` from the DNS event (`None` for HTTP) |
| `crates/fah-api/src/events.rs` | test `a_forwarded_query_names_its_answering_endpoint_and_a_cache_hit_does_not`: `endpoint = Some(1)` encodes to `data.endpoint == 1`; a cache hit encodes with no `endpoint` key |

Decisions:

- Absent, not `null`, on cache hits / blocks / HTTP items — matches the
  event's own serde rule and keeps every pre-change consumer byte-identical
  on those rows. This is the one key on the shape that is not always present;
  API.md §WS must say so.
- `upstream` stays `null` and `answer` stays off the feed — out of scope by
  the task's strict boundary.
- No `fah-dns`/`fah-model` change; no hot-path change (one `u8` copy inside
  the per-event DTO build that already runs only when a socket is connected,
  `EventHub::has_subscribers`).

Tests/gates: `cargo fmt --check`, `clippy --all-targets -D warnings` clean;
`cargo test -p fah-api -p fastadhunter` 151 passed. Full workspace run and the
0.2.18 image rebuild are in progress under p2.5-09.

Deferred / owner-gated:

- API.md §`WS /api/v1/events`: add `endpoint` to the documented `query` shape
  and replace the "attribution is aggregate-only" paragraph. Proposed diff
  presented in chat; not applied.
- tui-monitor: unaffected (no `deny_unknown_fields`), renders the key only if
  a later change chooses to.
- Live observation (p2.5-09 V5b) happens after the 0.2.18 deploy.

### Minor

**m1 — stale doc comment contradicts the field under it**
(`crates/fah-api/src/wire.rs:146-148`). The `upstream` field's comment still
says per-query upstream attribution "would cost an allocation on the hot
path"; `endpoint` now sits directly below it at zero cost. Code is correct;
the comment misleads the next reader into believing attribution is
impossible. Rule 7 stops an agent adding comment lines, not deleting them —
a fix is the deletion of the three stale lines (or the owner rewrites
them). Recommended before `DONE`; trivial.

**m2 — HTTP arm untested.** `From<QueryRecord>` returns `endpoint: None` for
an HTTP event; no test pins that an `http` item never carries the key. The
existing key-set test covers a DNS block only. One assertion on an HTTP
record closes it. Recommended before `DONE`; trivial.

### Nitpick

**n1** — test helper `forwarded_event(endpoint)` derives `cache_hit` and
`upstream_used` from `endpoint.is_none()/is_some()`. Correct for the two
cases used, but the coupling is implicit; two explicit helpers
(`forwarded()`, `cache_hit()`) would read straighter. Deferred.
