### U2 — layering guard rewrite (`crates/fastadhunter/tests/layering.rs`)

Full rewrite, comment-free (the former `//!`/`///` text lives here now).

- **Member discovery:** parses the workspace root `Cargo.toml`
  `[workspace] members` (`["crates/*", "tui-monitor"]`), expands `<dir>/*`
  via `fs::read_dir` (directories only), accepts literal paths, panics on any
  other glob shape, and requires every expanded member to have a
  `Cargo.toml`. The hardcoded `checked == 11` is gone; the test asserts
  `checked == members.len()`, that `fah-tui-monitor` was among them (so the
  allowlist branch actually ran), and that more than one crate was found.
- **Dependency name resolution:** real crate name = the `package` field when
  the entry's value is a table carrying one, else the key. The `fah-` filter
  and the layer assertion both run on the real name, so
  `x = { package = "fah-dns" }` is caught and `fah-x = { package = "serde" }`
  is correctly ignored.
- **Tables scanned:** `dependencies`, `dev-dependencies`,
  `build-dependencies`, and each of those three under every
  `target.<cfg>` table.
- **Policy unchanged:** the L1–L4 ladder in `layer()` is byte-identical;
  ladder crates still require every internal dependency to be strictly
  lower; an unknown crate (either as a member or as a dependency) still
  panics. `fah-tui-monitor` is not in the ladder — it gets an explicit
  allowlist, internal deps ⊆ `{fah-model}`.
- Test-only: no production code, dependency, or manifest changed. `toml`
  was already a dev-dependency of `fastadhunter`.
- Invocation unchanged: `cargo test -p fastadhunter --test layering`.
- The guard passed on the unmodified tree before the rewrite (1 passed) and
  after it (1 passed) — no latent violation existed.

### Known limitations

- Member globs other than `<dir>/*` are rejected rather than expanded; the
  workspace uses only that form.
- `[workspace] exclude` is not consulted (the workspace has none).
- A member entry `x = { workspace = true }` is resolved by its key only; a
  `[workspace.dependencies] x = { package = "fah-…" }` rename would bypass
  the guard (M2). No `fah-*` crate is in `[workspace.dependencies]` today;
  close when one is added.

`docs/project-state.md` §Open unknowns still lists "IPv6 upstream forwarding

**M2 — `workspace = true` renames bypass `real_name`.**
`layering.rs` resolves `package =` only on the member's own table. A member
entry `dnsx = { workspace = true }` backed by
`[workspace.dependencies] dnsx = { package = "fah-dns", … }` yields the name
`dnsx`, which fails the `fah-` filter and is never checked. Today
`[workspace.dependencies]` holds no `fah-*` crate, so no live gap. Impact if
left: the rename bypass the task set out to close survives through one
indirection. Defer; note in Known limitations. Evidence: inference from code
plus `grep` of root `Cargo.toml`.

**M3 — example config activates the RouterOS password key.**
`config.example.toml` sets `password = "PASTE-ROUTEROS-PASSWORD"` where the
former tracked file had it commented out with the `$MP` fallback. A copy
that fills host/port/token and leaves the rest sends the literal placeholder
to the router on every poll (`resolved_password` prefers the configured
value). Impact: silent auth failures in the footer, possible RouterOS login
lockout noise. Fix before DONE: comment the key out as the original did.
Evidence: measured (`config.rs:334`, both files).
