# On-prem fixes & 0.2.4 features — review

Work that came out of the p1.5-07 on-device run (RB5009, 2026-07-24). Shipped in
image **0.2.3** (the deploy fixes) and **staged for 0.2.4** (the three features).
All gates green; nothing committed yet (batch-commit on explicit go).

## Shipped in 0.2.3 (deploy fixes, verified live)

### 1. `/data/history` permission bug (correctness)

**Symptom:** every history/perf flush logged `failed to append … Permission
denied (os error 13)`; nothing landed on `/data/history`.

**Cause:** `stats.boot()` runs as **root** (before the ADR-0004 privilege drop)
and its writers `create_dir_all(/data/history/{rollups,perf})`, so those dirs are
born root-owned. The drop then calls `reown_if_needed(/data)`, which takes a
top-level shortcut — if `/data` is already owned by the service user (seeded
image / prior run) it returns without descending — so the fresh root-owned
subdirs are never re-owned, and the post-drop uid 65532 can't write them.

**Fix** ([main.rs](../../crates/fastadhunter/src/main.rs)): name the state
subdirs explicitly in the drop so each is re-owned even when `/data` is already
the service user's:

```rust
let history_dir = data_dir.join("history");
let query_log_dir = data_dir.join("query_log");
privilege::drop_to_service_user(&[config_dir, data_dir, &history_dir, &query_log_dir])?;
```

Reuses the tested `reown_tree` walker (cheap: skips subtrees already owned), and
recovers a volume a prior broken 0.2.1 boot left root-owned. Verified on device:
boot now logs `adopting state directory … /data/history`, no EACCES.

### 2. Unreadable logs — ANSI on a non-TTY (usability)

RouterOS captures the container's stderr (not a TTY), but `tracing_subscriber`
defaults `with_ansi(true)`, so colour escapes printed literally (`1B[2m…`),
making the log unreadable. Fix ([fah-logging](../../crates/fah-logging/src/lib.rs)):
`.with_ansi(false)` on the text layer.

### 3. Boot dedup log spam (usability)

Every list refresh recompiles the whole ruleset, so the per-compile "removed
duplicate rules across lists" line printed **once per list** (16 identical INFO
lines on the boot refresh). Fix: that line → `debug`; a single named
`list refreshed list=… rules=…` INFO line per list in `refresh_list`. `debug` is
below the default `info`, so it never shows unless the level is raised.

(The `::` dual-stack listen default that also shipped in 0.2.3 is the user's own
`listen.rs` edit, not part of this review.)

## Staged for 0.2.4 (uncommitted, tested)

### 4. User-rules exact-duplicate dedup on write

`PUT /rules/user` stored whatever it was sent, so posting the same rule twice
persisted a literal duplicate (the matcher deduped it, but the stored list
carried clutter). Fix ([routes.rs](../../crates/fah-api/src/routes.rs)
`put_user_rules`): drop exact-duplicate rule lines, keep the first, preserve
order; blanks and comments pass through (no matcher identity to collapse). Test:
`user_rules_put_drops_exact_duplicates_preserving_order`.

### 5. `POST /api/v1/lists/refresh` — refresh all

Refresh every enabled list in one pass and compile the ruleset **once**, not
once per list (looping the per-list route = N full 683k-rule compiles, the
boot-storm). Best-effort: a failed fetch is reported and skipped, the rest still
refresh; synchronous, returns `{ refreshed, failed, results:[{id,status,…}] }`.

Clean: the fetch+commit half is extracted into a shared `fetch_and_commit`
helper that both `refresh_list` and `refresh_all` use — no duplicated logic.
Fetches stay sequential (RB5009 RAM discipline). Route registered as a static
segment before `/lists/{id}` (static wins in matchit, so a list can't shadow it).
Docs: API.md, `requests/lists.http`. Test:
`refresh_all_refreshes_every_list_best_effort_and_reports_each` (proves a failing
list doesn't abort the batch and the good one still serves).

### 6. `upstreams.timeout_ms` default 2000 → 800

On-device stress showed 2000 ms burned a client's whole timeout budget before
failover even started, so successful fallbacks arrived too late. 800 ms fails
over inside a typical client's 1–5 s budget while staying above a legitimately
slow recursive lookup (cold cache, distant TLD, DNSSEC). Changed the code default
and the reference-TOML fixture (round-trip test green), CONFIGURATION.md, and
settings.http. The running router already had 800 persisted via a live
`POST /config`.

### 7. TCP client-disconnect no longer warns (usability)

A DNS-over-TCP client hanging up mid-response logged `WARN … TCP DNS connection
ended with an error error=Broken pipe`. That's routine — happy-eyeballs dropping
the loser, a UDP answer that arrived first, a client timeout — not
operator-actionable. Fix ([tcp.rs](../../crates/fah-dns/src/tcp.rs)): classify
`BrokenPipe | ConnectionReset | ConnectionAborted | UnexpectedEof` as a client
disconnect and log those at `debug`; genuine faults still `warn`. (A clean close
*between* messages was already returned as `Ok`.)
