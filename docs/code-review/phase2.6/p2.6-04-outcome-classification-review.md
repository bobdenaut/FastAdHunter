### Decisions

- **`classify` lives in `health.rs`, not a sibling `classify.rs`.** The plan
  allowed either. One function and two enums do not earn a module; `Outcome`
  is already here and the only import cost is `std::io` and
  `hickory_proto::op::Message`, neither of which performs I/O.
- **`Ok(_)` is `Success` without inspecting the message.** RCODE is never read
  — the strongest form of "no Stage 1 transition can be triggered by NXDOMAIN,
  SERVFAIL or REFUSED" (S1.4), and it makes the TC → TCP-retry and
  idle-close → reconnect → answer rows fall out for free: both return `Ok`
  from `UpstreamServer::query`, which is the only value `classify` sees.
- **The catch-all arm is `_`, not an enumeration of kinds.** `io::ErrorKind`
  is `#[non_exhaustive]`; an exhaustive list would need a `_` arm anyway, and
  a future kind defaulting to `HardFailure` is the safe direction — a hard
  failure needs `penalty_failures` occurrences before it penalizes, a path
  failure penalizes at one. The test at `health.rs:1044-1073` pins eleven
  named kinds through that arm so a mis-slotted kind is caught.
- **`HealthMode` is a bare enum with no behaviour.** `Ignore` must skip the
  `attempts` counter too (S1.8), and the counters are moved by the pool, not
  by `health::record` — so a `record_mode(mode, ..)` wrapper here would cover
  the packed word only and give a false guarantee. The skip belongs where all
  the mutations are, in p2.6-05.
- **`classify`, `HealthMode` and `TransportKind` are re-exported from
  `lib.rs`** with the rest of the health surface. `upstream` is a private
  module, so a `pub` item unreachable from the crate root is dead code under
  `-D warnings`; this also keeps the p2.6-08/p2.6-09 benches, which are
  external targets, able to drive them.

### Known limitations / deferred

- **The `Ignore` acceptance criterion cannot be asserted in this task.** "A
  failing attempt leaves every `Health` field unchanged" needs the attempt
  loop, which p2.6-05 owns; no `Health` is wired to any transport yet. Same
  for G1 #14's end-to-end half and for `TransportKind` being read from
  `Transport` once per attempt — both are p2.6-05 call-site work.
- **The UDP path-failure row is not exercised on the dev box.** Windows
  reports ICMP port unreachable as `ConnectionReset` (hard), Linux as
  `ConnectionRefused` (path). Spec S1.4's platform note; p2.6-09's B.2 UDP arm
  is `cfg(target_os = "linux")`. The dev-box evidence is the DoT-on-a-closed-
  port route, which yields `ConnectionRefused` on both platforms.
- **`InvalidData` on the encrypted transport is assumed to mean TLS.** True
  today (`transport_error_kind` produces it only for a `rustls::Error` in the
  chain, and `tokio-rustls` stamps it on a certificate rejection — p2.5-04).
  If a future producer emits `InvalidData` there for a non-TLS reason it would
  silently become a path failure. Not detectable by a test that does not know
  the future producer; the p2.5-04 kind tests are the tripwire.
- **Attacker-triggerable timeout is documented, not mitigated** (S1.4) —
  explicitly a non-goal.
