## Decisions

- **`state`/`penalty_round` are not gated on strategy.** Under `fallback` the
  packed word is never written, so it reads back as its `Health::default()`
  zero — `Healthy`, round 0 — which is exactly what S1.12 requires. A strategy
  match would have been dead code. `consecutive_failures` keeps its existing
  match: under `fallback` it lives on `UpstreamServer`, under `adaptive` in the
  word.
- **The degraded rule is a free fn over `&[UpstreamStatus]`, not a method.** It
  is the only new policy in this task and it is pure; a free fn is unit-testable
  with hand-built rows, so the six `/health` cases need no network, no timers
  and no test seam widened on the pool. `TelemetryAdapter::degraded` is now one
  line.
- **`family` is stored, never looked up.** `UpstreamServer::new` already parses
  the `SocketAddr` (udp/dot) and matches `url.host()` (DoH); both branches now
  yield the family alongside the transport. A hostname DoH endpoint reports
  `None` — no boot-time resolution, per the owner's 2026-08-23 resolution.
- **`penalized_seconds_total` is the nominal accrual, jitter excluded.**
  `penalize()` reports `nominal_penalty(round)` in `penalty_applied` while the
  stored deadline carries the ±25 % jitter, so the counter is exactly
  `sum(nominal)` and the test asserts an exact 60 / 180, not a band.
- **The collapse dropped two `fah-dns`-only doc comments** (F1): `address`
  "the stable identity for metrics labels" and `tls_handshakes` "staying flat
  while `attempts` grows is the connection-reuse proof (p1-06 acceptance)".
  They lived on the deleted struct; re-adding them on `UpstreamSample` is a
  new comment, which hard rule 7 forbids. The reuse proof stays recorded in
  the p1-06 review.
- **Two doc comments edited, none added.** Plan step 5 authorizes only the
  `consecutive_failures` doc comment in both structs ("**Not a liveness
  signal** — `state` is … freezes while Penalized"). M5's "the field doc
  comments say so" for `attempts`/`failures` was **not** implemented here: those
  fields carry no doc comment today, and adding one is a new comment, which
  step 5 and hard rule 7 forbid. The `resolve_host` coverage change is p2.6-07's
  API.md line.

### Findings

**F1 — Minor — `UpstreamStatus` is now a field-for-field duplicate of
`fah_model::UpstreamSample`**

`fah-dns/src/upstream/mod.rs:85-109` and `fah-model/src/perf.rs:147-174` carry
the same 14 fields in the same order with the same types — after this task both
sides use `fah_model::Protocol`, `UpstreamState` and `AddressFamily`. The sole
consumer is the manual 14-line copy at `main.rs:701-716`. Rationale: `fah-dns`
already depends on `fah-model`, so the mirror buys no decoupling and violates
CLAUDE.md principle 4 (shared shape in exactly one place). Impact if left: every
future endpoint-telemetry field costs a second struct edit plus a mapping edit,
and a field forgotten in the mapping is a silent zero on `/telemetry` that no
test catches — this task already paid that cost across seven sites. Evidence:
inferred from the two definitions; no runtime cost either way (the mapping moves
values, it does not clone). Smallest remediation: `pub type UpstreamStatus =
fah_model::UpstreamSample;` in `fah-dns`, deleting the mapping. **FIXED**
(owner-approved 2026-08-24) — see §Fixes applied.

**F2 — Minor — the `penalized_seconds_total` semantic lands in no comment and no
document**

`p2.6-06-telemetry.md` §Scope requires "its doc comment says *scheduled
unavailability*". No doc comment was added (`perf.rs:166-167`, `mod.rs:104`).
The plan's step 5 forbids new comments and the plan wins where the two differ,
so the omission is defensible — but the field name reads as "seconds spent
penalized" while the counter is the nominal `penalty(round)` banked at
application and never advanced while the endpoint sits Penalized. Impact if left:
an operator reads a flat `60` through a ten-minute outage and concludes the
penalty expired. The Decisions section records the choice; §Remaining TODOs does
**not** list it among p2.6-07's API.md items, so it can be lost. Evidence:
inferred. **FIXED in p2.6-07's task file** (owner-approved 2026-08-24) — see
§Fixes applied.

**F3 — Minor — perf-history growth was asserted trivial, never computed**

Plan step 6 conditioned persistence on a row cap only; §Remaining TODOs repeats
"no row byte cap" without a figure. None of the seven fields carries
`skip_serializing_if`, so every row writes all of them, including the six that
are constant under `fallback`. Measured from the emitted key names,
`,"state":"healthy"…,"family":"v4"` is ~123 B per endpoint per sample; at one
sample per 60 s that is 0.35 MB/day for two endpoints and 1.4 MB/day at the
8-endpoint cap, against the default `history.retention_days = 30`
(`fah-config/src/schema/history.rs:44`, `lib.rs:531`) — ~10 MB and ~43 MB of
retained `/data` on the RB5009. Hard rule 4 still holds (bounded by retention,
not by uptime or traffic) and this is disk, not RSS. Evidence: byte count
computed from the field names; sample cadence and retention read from config;
on-device file size **not** measured. **CARRIED to p2.6-11, no code change**
(owner decision 2026-08-24) — see §Fixes applied.

**F4 — Nitpick — `degraded()` allocates a `Vec<UpstreamStatus>` per `/health`
request to read two fields**

`adapters.rs:235-237`: `status()` clones every endpoint's address `String` and
builds the full row so `upstreams_degraded` can compare `state` or
`consecutive_failures`. Pre-existing — the previous body called `status()` the
same way — so this is not a regression, and the free-fn shape is what makes the
six `/health` cases unit-testable. Noted only because the new predicate is the
natural place a cheaper accessor would attach. **Deferred**, no action needed.

**F5 — Nitpick — the plan's `family: None` round-trip test is absent**

Plan §Tests names "a round-trip with `family: None`". `perf.rs:263-275` proves a
row that *omits* the key reads back `None`; nothing serializes `None` and reads
`"family":null` back. `Option<AddressFamily>` with `#[serde(default)]` accepts
both, so there is no defect — only the named case is missing, and it is the case
a hostname DoH endpoint produces on every persisted row. Evidence: inferred from
serde semantics; not exercised. **FIXED** (owner-approved 2026-08-24) — see
§Fixes applied.

### Categories checked, no issue found

- **Correctness / concurrency.** `status()` takes one relaxed load of the packed
  word and separate relaxed loads of the six counters, so a row is not a
  consistent instant. Checked the two orderings that could produce an impossible
  row: `probes` increments at claim (`mod.rs:358`) before `probe_successes`
  (`mod.rs:392`) and is read first, so `probe_successes > probes` cannot appear;
  `penalties` before `penalized_ms_total` (`mod.rs:381-384`), same read order.
  Worst case is a sub-microsecond skew on a 10 s poll. `unpack` is total — no
  panic on any bit pattern, `debug_assert` only.
- **Architecture / layering.** `fah-model` gained two `Serialize`/`Deserialize`
  data enums and no logic (hard rule 2); `family_of` stayed in `fah-dns` rather
  than becoming a `From<IpAddr>` in `fah-model`. `fastadhunter` (L4) importing
  `fah_config::UpstreamStrategy` (L1) and `fah_dns::UpstreamStatus` (L3) points
  downward; `layering.rs` green.
- **Performance.** Nothing added to the query path: the only new work is one
  extra relaxed load per endpoint on the 10 s poll, plus a `Copy` field read for
  `family`. `UpstreamServer::family` is computed once in `new` from an already
  parsed `SocketAddr`/URL host — no boot-time or per-poll resolution.
- **Memory.** `UpstreamSample` grows by ~40 B (four `u64`, two one-byte enums,
  one `Option`), bounded by the 8-endpoint cap in both the `ArcSwap` snapshot
  (`registry.rs:75`) and the poll vector. `Health` is unchanged and its
  `size_of == 64` assertion still holds. Disk growth is F3.
- **Rust quality.** No new `unwrap`/`expect`/`panic` outside tests; the
  `State → UpstreamState` match is exhaustive; no new clone (`address` is moved
  in the mapping); `upstreams_degraded` borrows a slice.
- **Regression.** `fallback` behaviour is unchanged: `state` reads back from a
  never-written word as `Healthy`, `consecutive_failures` keeps its existing
  strategy match, and `fallback`'s degraded rule and its `/health` test
  (`fah-api/tests/api.rs:677`) are untouched. `swr.rs:508-514` and the
  `encrypted.rs` status assertions still compile and pass unmodified. No WS or
  Prometheus surface publishes upstream fields, so nothing else drifted.
- **Tests.** The two `status()` tests drive real sockets through `forward` and
  make the deadline due by rewriting the word's timestamp rather than sleeping,
  so no wall-clock dependence and no flake window. The six `upstreams_degraded`
  cases are table-free but cover empty, all-Penalized, mixed-with-Probing,
  one-Healthy, frozen-streak-on-Healthy and `fallback`.
