## S1-M readiness

**The path S1-M measures.** M.1/M.2 → `health::select(&[Health], 0, || const,
true)`: one `state.load()` (Relaxed) → `unpack` → `State::Healthy` arm →
return, before `clock.take()` (`health.rs:339-344`). M.5 → `health::record(..,
Outcome::Success, .., &Policy)`: one `state.load()` → `(Healthy, Success)` with
`consecutive_failures == 0` → `Transition::NoChange`, **no store, no clock**
(`health.rs:236-238`). These are the same two calls `walk_adaptive` makes at
`mod.rs:319` and `mod.rs:344` — the bench measures the shipped path, not a
proxy.

**API sufficiency.** `select`, `record`, `next_word`, `pack`, `unpack`,
`penalty`, `Health`, `Policy`, `Outcome`, `State`, `Word`, `Candidate`,
`Selected`, `PackedWord` are all re-exported at `fah_dns` (`lib.rs:23-26`).
Synthetic Penalized/Probing words are buildable from the external bench target
via `pack(..)` + `PackedWord::store(..)`; the plan's conditional
`#[doc(hidden)] pub fn from_word` is **not needed**.

**Zero-allocation assumption.** `select` and `record` allocate nothing —
`LazyNow`, `Word`, `Candidate`, `Transition` are all stack values, no `Vec`,
`Box` or `Arc` is created on the walk. `tests/forward_alloc.rs` asserts
count-equality between strategies end to end and passes. Note the criterion is
*equality*, not literal zero: the shared UDP mock allocates inside the same
`block_on`, identically in both arms.

**Clock-read assumption.** Verified at both sites above. Caveat the bench must
not break: `select` samples the closure **only** in the `Penalized if claim`
arm, so M.3/M.4's "clock evaluated once" holds only while every arm passes
`claim = true`, as the plan specifies.

**Hidden work added by 01–06.** Per attempt, `adaptive` adds one relaxed load +
`unpack` (select), `classify` (two matches on values already in hand), and one
relaxed load + `unpack` + compare (`record`). No allocation, no lock, no clock,
no syscall on the healthy path. `ProbeGuard` is constructed only when
`selected == Probe`; on the healthy path it is `None`. `status()` (p2.6-06) is
off the query path. Nothing added between p2.6-01 and p2.6-06 invalidates the
microbench. The one measurement hazard is F3, and it sits in the M.8 sibling
arm, not in M.1/M.5.

## Findings

**F1 — Major — the probe claim uses `compare_exchange_weak` with no retry loop.**
`crates/fah-dns/src/upstream/health.rs:352`. A spurious CAS failure is
indistinguishable from a lost race, so on an LL/SC target — ARM64, the
RB5009 — a pass can drop a claim it should have won, leaving **zero** probes
claimed for that query and deferring recovery by one query. On x86 `lock
cmpxchg` never fails spuriously, so the dev box cannot observe it. The tests
already work around it: `claim_probe` loops `CLAIM_ROUNDS = 8` passes and
`race_for_the_claim` re-seeds and re-races up to 8 rounds, each panicking if no
probe is claimed (`health.rs:1004-1023`) — the implemented guarantee is *at
most* one claim, not *exactly* one. Spec S1.7's "a lost CAS is not retried"
is about a lost race; a spurious failure is not one.
*Impact on p2.6-08:* benchmarks doc M.7 accepts on "winner count exactly 1 per
batch". On the dev box the bench will read 1, so S1-M is not blocked, but the
bench must either reuse the tests' retry harness or record that it measures
"≤ 1 winner, ≥ 1 within 8 passes".
*Smallest remediation:* add `compare_exchange` (strong) to `PackedWord` and use
it at `health.rs:352`. One call site, no behaviour change on x86.

**F2 — Minor — spec S1.6 contradicts the implementation and all four documents.**
`docs/design/adaptive-upstream-selection.md:520` says "`penalty_round` resets to
0". `next_round` returns **1** (`health.rs:174-180`) and the round is stored
only at penalize time, so 0 is only ever the pre-first-penalty value — which is
what S1.6's own next paragraph, CONTEXT.md §Penalty Round and API.md all say.
*Remediation:* "resets to 0" → "restarts at round 1", one line. Spec edit,
owner approval.

**F3 — Minor — `bench_refused`'s adaptive arm is time-fragile.**
`crates/fah-dns/benches/upstream.rs:88-110` builds the pool at
`timeout_ms = 2_000`, so the round-1 nominal penalty is 60 000 ms, jittered to
45–75 s. `forward_udp_refused_adaptive_penalized_forced` measures the forced
path only while that deadline stays in the future. Criterion's default warm-up
plus measurement is ~8 s, so it holds today; raising `measurement_time` in
p2.6-08/09 silently turns the arm into a probe-claim loop with an escalating
`penalty_round` and a growing deadline, and the arm stops measuring what it is
named for.
*Remediation:* build that arm through `UpstreamPool::with_policy` with a
`penalty_base_ms` well above the run length, or state the constraint in the
p2.6-08 results file. **Settle before numbers are taken.**

**F4 — Minor — p2.6-07 is complete in the working tree but the phase table says
`WAITING`.** Four `.md` files are edited, `p2.6-07-docs-review.md` exists and
concludes `PASS WITH DEFERRED FINDINGS`, and nothing is committed
(`plan/wip/phase2.6-adaptive-stage1/CLAUDE.md` row 7). The phase algorithm
selects the lowest `WAITING` task, which is 07, not 08.
*Remediation:* commit the p2.6-07 changeset and mark row 7 `DONE` — owner's
call, per the working agreement. **Settle before p2.6-08 starts.**

**F5 — Minor — two tasks edited `.md` files they did not own.** `59c85a0`
(p2.6-01) touched `docs/design/adaptive-upstream-selection-benchmarks.md`, ADR
`...hot-path-event-without-a-schema-break.md`, the phase `CLAUDE.md` and three
sibling plan files, while its own acceptance criterion reads "No `.md` edited".
`0159cf7` (p2.6-05) added 7 lines to `CONFIGURATION.md`, which its plan lists
under p2.6-07's non-goals. Both are named in the owning commit message as
review follow-ups, so this is bookkeeping rather than silent scope creep, but
neither task met the criterion as written.

**F6 — Nitpick — `nominal_penalty` guards the shift amount, not the value.**
`health.rs:167-173`: `checked_shl` only rejects shifts ≥ 64, so
`penalty_base_ms << 14` wraps silently for a base above 2⁵⁰ and can yield a
value *below* the base. Unreachable through config (base ≤ 300 000) but
reachable through the `#[doc(hidden)] pub with_policy` seam p2.6-09's bench
uses. A saturating doubling loop, or `checked_mul(2)` per round, makes it total.

**F7 — Nitpick — `PackedWord::store` is `pub`.** It is the bench seam for
synthetic words and p2.6-08 needs it, but it also lets any `fah_dns` consumer
write state bits `3`, the value `unpack` `debug_assert`s against.
`#[doc(hidden)]` on `store` keeps the seam and marks it as one.

### Observation, not a finding

Forced attempts pile onto a Probing endpoint during a total outage. `select`'s
forced pick is the smallest `timestamp_ms` among Penalized **and** Probing
words, and a claimed probe keeps its already-passed deadline
(`health.rs:346-351`), so a Probing endpoint is almost always the earliest.
Under concurrent load in a full outage every forced attempt lands on it and
follows the Probing row: `penalty_round += 1`, a new deadline, `penalties += 1`.
`penalty_round` can therefore reach 15 and `penalized_seconds_total` accrue far
faster than one penalty per window. This is exactly what S1.3 specifies, and
G1 #6 deliberately asserts invariance on the Penalized row only — but it is a
telemetry-reading trap that neither API.md nor measurement-traps.md states, and
p2.6-09's outage rows will show it.
