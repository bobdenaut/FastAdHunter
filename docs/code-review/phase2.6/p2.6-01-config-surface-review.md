### Decisions

- **Eight literal sites, not nine.** `crates/fastadhunter/src/main.rs:1046`
  already ends in `..fah_config::DnsUpstreamsConfig::default()`, so it needed
  no edit. The plan's count assumed nine.
- **`..Default::default()` instead of `penalty_failures: default_penalty_failures()`.**
  The plan allowed either. This keeps `default_penalty_failures` private
  instead of adding a function to `fah-config`'s public API through three
  re-export lines, and matches the existing style at the `main.rs` site. Cost:
  one dropped default `Vec<UpstreamServerConfig>` per call, in test/bench
  setup only.
- **`penalty_failures` upper bound 255**, not `u32::MAX` — the pool narrows it
  to `u8` at construction (p2.6-05); a value above 255 would silently truncate.
- **Field placed before `servers`** — TOML requires scalars ahead of the
  array-of-tables, so `to_toml_string` stays reparseable.
- **Doc comment on `UpstreamStrategy`** ("Only `fallback` … is implemented
  today") left untouched: still true until p2.6-05, and rewriting it is a
  comment edit the hook rejects.

**F3 — RECORDED IN p2.6-11 (2026-08-23) — rollback after a config write-back
is the S1.14 trap in reverse.**
Fix applied: `p2.6-11-optin-deploy-soak-plan.md` step 2 now carries a
**Rollback note** requiring `penalty_failures` to be removed from

`to_toml_string` (`lib.rs:68-70`) serializes every field; `Config::save`
(`lib.rs:85`) and first-boot generation (`lib.rs:48`) therefore write
`penalty_failures = 2` to disk. After any `POST /api/v1/config` on the new

`deny_unknown_fields` on the file the new binary wrote. Spec S1.14 fixes the
forward order (binary first, config second); the rollback procedure in
p2.6-11 should state that a rollback needs the key removed from the file
first. No code change proposed — `skip_serializing_if` on a default would
hide the key from `GET /api/v1/config` and contradict "the file always
reflects the effective config". Evidence: inference from the serializer
attributes; not exercised by a test.

### Categories checked, no issue found

- **Correctness.** Validation runs after env overrides (`lib.rs:55-56`), so
  `FAH__DNS__UPSTREAMS__PENALTY_FAILURES=0` is rejected at boot; `POST
  /api/v1/config` goes through `Config::validate` (`lib.rs:76`). Range checks
  moved ahead of the `servers` checks — order is irrelevant, every check is
  independent. `u32` → `coerce_u32` → `1..=255` leaves no truncation path for
  the `u8` narrowing in p2.6-05. No concurrency, lifecycle or cancellation
  surface in this task.
- **Architecture.** Layering unchanged; no new dependency, type or public
  function (`default_penalty_failures` stays private; `..Default::default()`
  was the plan's permitted alternative). `dns.upstreams` remains boot-only
  without an API edit. No Stage 2/3 key added (`deny_unknown_fields`
  permanence respected).
- **Performance.** No hot-path file touched. `validate` is load/POST-only.
  `..Default::default()` costs one `Vec<UpstreamServerConfig>` (two `String`s)
  per call and every call site is test or bench **setup**
  (`benches/upstream.rs:62, 75` run `pool_for` once outside `b.iter`) — bench
  figures unaffected.
- **Memory.** `Config` grows by 4 B. No retained state, no buffer, no task.
- **Rust quality.** No `unwrap`/`expect` outside tests; `UpstreamStrategy`
  stays `Copy`; `FromStr::Err = &'static str` matches `coerce_enum`'s bound;
  TOML field order (`penalty_failures` before `servers`) keeps
  `to_toml_string` reparseable — asserted by the round-trip test.
- **Tests.** Every §Tests item in the plan has a test; each asserts the
  specific `ConfigError::Validation { key }` or `InvalidEnvValue`, not just
  `is_err()`. None is timing-dependent. Pre-existing `fah-config` tests
  unmodified (diff shows additions only).
- **Regression.** Cap 255 → 8 is the authorized C1 decision; a deployed
  config with 9–255 servers or `timeout_ms > 10 000` now fails boot — both
  accepted in the plan, neither known to exist, RB5009 default has 2 servers
  at 800 ms. `fallback` behaviour and its test assertions untouched
  (`server_integration.rs`, `encrypted.rs`, `mod.rs` diffs are the one
  inserted line each).
