### Algorithm

One `for` over `health.iter().enumerate().skip(start)`, one relaxed load per
endpoint, judging each word where the pass meets it (S1.5):

- `Healthy` → return `Selected::Healthy`, clock untouched.
- `Penalized` with `claim` → sample the clock (memoised), and when
  `deadline <= now`, one `compare_exchange_weak` Penalized → Probing
  preserving `penalty_round`, `consecutive_failures` and `timestamp_ms`;
  success returns `Selected::Probe`. A lost or spurious CAS failure is not
  retried — the pass continues and the endpoint becomes a forced candidate.
- `Probing` → skip, forced candidate.
- Pass exhausted → the remembered smallest `timestamp_ms` as `Selected::Forced`,
  nothing stored (S1.3 hard invariant).
- `None` only when the range from `start` is empty.

### Decisions

- **Clock memo is `Option<u64>` + `Option<F>`.** `get_or_insert_with` on the
  memo takes the `FnOnce` out of its own `Option`, so the closure is called at
  most once per pass and never on a pass that meets a Healthy word first
  (S1.11). It is sampled at the first *Penalized* word reached with
  `claim = true` — a `Probing` word needs no clock, and a `claim = false` pass
  none at all (F2) — a strict subset of the spec's "first non-Healthy word"
  that still satisfies "at most once".
- **Forced candidate uses strict `<`**, so a tie on `timestamp_ms` keeps the
  lower id, i.e. config order.
- **A lost CAS still registers the endpoint as a forced candidate.** Its word
  is now `Probing`, and Probing words are forced candidates (validation H3), so
  registering it costs no extra load and keeps the hard invariant total.
- **`claim` is a plain `bool`** — no reference to `HealthMode` (p2.6-04); the
  mapping happens at the p2.6-05 call site (validation B2).
- **The selector moves no counter**, `probes` included; p2.6-05 owns accrual,
  as `record` does for the word's counters (p2.6-02 decision C3).
- **`id: u8` via `u8::try_from(index).unwrap_or(u8::MAX)`**, matching
  `ForwardOutcome`'s existing narrowing in `upstream/mod.rs:227`. The config
  surface caps endpoints at 8 (p2.6-01).

### Findings

**F1 — Minor — probe-claim tests assume the weak CAS cannot fail spuriously**
`health.rs:279` uses `compare_exchange_weak` (spec S1.7, correct). On LL/SC
targets (ARM64 — the shipping target) a spurious failure is legal with zero
contention, so `due_endpoint_ahead_of_a_healthy_one_is_probed` (`:799`),
`a_deadline_equal_to_now_is_due…` (`:921`) and both G1 #8 race tests
(`:862`, `:876`) can observe zero claims and fail. Production impact none — a
spurious miss just defers the probe one query, per spec. Inferred (architecture
property), not measured; x86 `lock cmpxchg` cannot fail spuriously, so the
dev-box gate is deterministic. The summary's deferred note covers only the #8
tests; the two single-threaded probe assertions are equally exposed.
**Deferred** — fix only if the suite ever runs on ARM64: bounded re-run of the
round, or tolerate one miss. No production change.

**F2 — Nitpick — `claim = false` pass samples the clock without using it**
`health.rs:269-272`: `sampled` is bound before `if claim && …`, so an
Ignore-mode pass meeting a Penalized word pays one closure call whose value is
dead. Matches the plan's step 2 text verbatim, so plan-compliant; cost is one
clock read per Ignore attempt over a non-Healthy pool (resolve_host ≈ 20 % of
attempts). M.1/M.2 budgets are unaffected (all-Healthy arms never reach it).
Inferred. **Deferred** — optional: move the memo inside `if claim`; revisit
only if p2.6-08 M-bench flags it.

### Categories checked, no issue found

- **Correctness** — CAS success proves the word was unchanged since the load

- **Rust quality** — `u8::MAX` id saturation at `:258` matches the existing

## Fixes applied (2026-08-23)

Both findings were approved for fix rather than deferral.

**F1 — fixed (tests only).** Two bounded-retry helpers replace the direct
`select` calls in the four claim assertions:

- `claim_probe(health, now_ms)` (`health.rs:882-890`) — up to `CLAIM_ROUNDS`
  (8) passes, returns the first `Selected::Probe`, panics otherwise. Used by
  `due_endpoint_ahead_of_a_healthy_one_is_probed` and
  `a_deadline_equal_to_now_is_due_and_one_millisecond_later_is_not`.
- `race_for_the_claim(health, word, now_ms)` (`health.rs:892-901`) — re-seeds
  endpoint 0 with `word` and re-runs the 8-thread round until one round claims,
  up to 8 rounds; panics otherwise. Used by both S1-G1 #8 tests, which still
  assert **exactly one** `Probe` inside the successful round.

A spurious `compare_exchange_weak` failure leaves the word untouched, so a
retry is a faithful repeat of the same starting state. A selector that never
claims still fails the test — after 8 rounds instead of 1. No production code
changed; the "1 probe, 7 losers" gate is unchanged.

**F2 — fixed (production).** The Penalized arm is now
`State::Penalized if claim =>` with a bare `State::Penalized => {}` arm behind
it (`health.rs:268-289`). The clock closure is no longer evaluated on a
`claim = false` pass, so an Ignore-mode attempt over a penalized pool reads no
clock at all — the memo lives inside the claiming arm. The forced-candidate
bookkeeping after the match is untouched, so both arms still register the
endpoint. `deadline_passed` is only meaningful when a claim can follow, so no
behaviour changed for `claim = false`: a due endpoint was already skipped.
