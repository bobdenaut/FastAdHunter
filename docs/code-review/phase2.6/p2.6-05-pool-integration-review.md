### Decisions

- **`record` now takes a lazy clock** (`now: impl FnOnce() -> u64`), the same
  shape `select` already had. The acceptance criterion is *zero* clock reads on
  the healthy path, and the plan's eager `record(.., elapsed_ms(epoch), ..)`
  reads one on every success. A private `LazyNow<F>` memo is threaded through a
  new private `next_word_lazy`; the public `next_word(word, outcome, now_ms,
  policy)` stays eager as a one-line wrapper, so the S1.3 table and its tests
  are untouched. Only the eight `record(..)` call sites in `health.rs` tests
  changed, by wrapping the literal in `|| …`; no assertion moved. Falls out for
  free: `(Healthy, HardFailure)` below threshold and `(Penalized, failure)`
  now read no clock either.
- **The alarm tail is shared, not duplicated.** `forward_with` keeps the
  existing `last_err` / `alarm.claim()` block verbatim; `walk_adaptive` returns
  `Result<ForwardOutcome, Option<io::Error>>` and feeds it. `Err(None)` is the
  empty-server-list case.
- **Two existing `fallback` tests changed accessor, not assertion.** C3 moved
  `attempts`/`failures` off `UpstreamServer`, so
  `pool.servers[i].attempts.load(..)` became `pool.health[i].attempts.load(..)`
  (three lines in `a_decoded_rcode_is_not_an_upstream_failure`, one loop in
  `a_walk_over_held_servers_is_bounded_by_the_per_server_bound_times_n`). Every
  asserted value and every message is unchanged; the rest of the suite is
  additions only.
- **G1 #6 uses a large `penalty_base` (60 s), not the plan's "tiny" one.** A
  tiny base makes the deadline pass while the test runs, which turns the forced
  attempt into a probe and contradicts the same test's `probes == 0`
  assertion. Large base ⇒ deterministic Forced path, which is what the
  criterion is about.
- **`dot_pool_adaptive` flips `pool.strategy` on a `dot_pool` rather than
  duplicating `dot_pool_from`.** Same for `adaptive_pool`, which overrides
  `policy` after `with_tls_config` instead of adding a second constructor.

**F1 — Should-fix — CLOSED — the refused bench arms measure different
state-machine paths**

Diagnosis unchanged: the endpoint cannot stay Healthy under `adaptive`.
`ConnectionRefused` is a `PathFailure` and penalizes on the first failure
(`health.rs:103-105`, `:264-269`); `ConnectionReset` (Windows) is a
`HardFailure` and penalizes at `penalty_failures = 2`. With
`penalty_base_ms = 10 × 3 × 2000 = 60_000` the deadline never passes inside a
criterion run, so every sample takes the Forced path.

Like-for-like is unreachable — no configuration keeps a refused endpoint
Healthy under `adaptive` — so the arms are named for the path they exercise
and made deterministic across platforms:

| Arm | Steady-state path per sample |
| --- | --- |
| `forward_udp_refused` (fallback, name unchanged, comparable to p2.5-07's 20.2 ms median) | ordered walk; the endpoint is tried every iteration; plain counters |
| `forward_udp_refused_adaptive_penalized_forced` (renamed from `forward_udp_refused_adaptive`) | `select` skips the Penalized word, returns it as `Forced`, attempts it, `record` takes the `(Penalized, failure)` row — `NoChange` once the run saturates at 255 |

`REFUSED_WARMUPS = 4` forwards run before the first sample on both arms, so
the adaptive endpoint is Penalized before measurement whichever `io::ErrorKind`
the host produces. `forward_udp_answered` / `forward_udp_answered_adaptive`
were already like-for-like (both Healthy, both success) and are untouched —
they remain the S1-G2 tier-1 pair. The path table above is the record p2.6-08
reads; the bench itself carries it in the arm names, since hard rule 7 forbids
a comment there.

**F2 — Minor — CLOSED — the 100-iteration `Ignore` test dominated suite
wall-clock**

*The count was examined first, as instructed, and kept.* It is not decorative:
the invariant is "no counter moves", and every threshold in the state machine
is crossed by repetition — `penalty_failures` (2 by default), the `u8`
`consecutive_failures` saturation at 255, and `penalty_round`'s cap at 15. A
one-iteration test passes against an implementation that penalizes on the
second attempt. 100 clears every threshold the S1.3 table can reach except the
255 saturation, so the count carries methodological weight and stays at 100.

Fixed by removing the cost instead: the mock's silenced AAAA leg is what each
iteration waits on, so `timeout_ms` drops 40 → 20 (a ~200× margin over a
loopback round trip, unchanged in kind). Measured: the `tests::adaptive` module
went **5.64 s → 2.74 s** while growing from 7 to 10 tests. Coverage is
identical — same 100 iterations, same assertions, same all-seven-atomics
snapshot.

**F6 — Nitpick — CLOSED — a claimed `Probing` word had no drop guard**

Assessed as instructed, and the guard is cheap enough to add rather than
defer. `ProbeGuard` (`health.rs`, `pub(crate)`, ~35 lines) snapshots the
claimed word, and on drop CASes `Probing` back to `Penalized` with the same
`penalty_round`, `consecutive_failures` and `timestamp_ms`.

Why it does not change current semantics:

- Built only when `Selected::Probe` was returned
  (`probe.then(|| ProbeGuard::new(health))`), so the Healthy path builds
  nothing and "one relaxed load, zero clock reads, zero allocations" holds —
  `tests/forward_alloc.rs` still measures a zero delta.
- The only await it spans is `server.query(..)`, and it is disarmed the
  instant that returns, before `classify`/`record`. Off the cancelled path the
  drop is one `bool` test.
- The restore CASes from the exact claimed word and retries only while the
  word is still that value, so it cannot overwrite a `record` that already
  moved the endpoint.
- Deliberately *not* rolled back: the `probes` counter, incremented before the
  attempt. A cancelled probe therefore counts once and the re-claim counts
  again. `probes` is an attempt counter for p2.6-06 telemetry, not a state
  bit, and a rollback would need the increment inside the guard for no gain.

Worth the lines despite being unreachable today: a stranded `Probing` word is
*not* self-healing while any other endpoint is Healthy — `select` returns a
Probing endpoint only as `Forced`, and `Forced` is reached only when the pass
finds nothing else, so the endpoint would be silently and permanently out of
rotation.

Verified by `a_cancelled_probe_returns_the_endpoint_to_penalized`: a
`tokio::time::timeout` drops `forward` mid-probe against a slow mock; the word
is asserted byte-identical to the pre-claim value. Negative control — with
`armed` forced to `false` the test fails `left: 70 (Probing) / right: 69
(Penalized)`, so the assertion proves the guard, not a coincidence.
