## Summary

- `adaptive` is the compiled-in `[dns.upstreams] strategy`; the `fallback`
  variant, its ordered walk in `forward_with`, the plain `consecutive_failures`
  counter on `UpstreamServer`, the `status()` arm and the `/health` streak rule
  are deleted. The pool no longer carries a `strategy` field.
- `strategy = "fallback"` in TOML, env (`FAH__DNS__UPSTREAMS__STRATEGY`) or a
  `POST /api/v1/config` body fails at load: `"fallback" was removed after
  0.3.3; "adaptive" is the only strategy`. The key stays (`deny_unknown_fields`);
  the enum keeps one variant for future strategies.
- Production is unaffected: the deployed config has said `adaptive` since
  2026-08-25 (p2.6-11 opt-in). Deploy order stays binary first, config second.
- Gates: fmt, clippy `-D warnings`, `cargo test --all-features --workspace` —
  52 binaries, 1467 passed, 0 failed, 9 ignored. `tests/layering.rs` unchanged.
- The G3 injected-failure suite loses its `fallback` control arms; the S1-G3
  figures they produced stay in the p2.6 review files.

## Decisions

- Gate precondition (plan step 1): S1-G2 tiers 2–3 passed; **S1-G4 and S1-G5
  route 2 closed unvalidated by owner decision** (p2.6-11 review, ROADMAP §2.6).
  The flip proceeds on the owner's explicit decision of 2026-09-07 recorded in
  this session, not on the gates.
- Single-variant enum with the `strategy` key kept (plan open item) — removing
  the key would make every existing TOML a boot failure.
- Rejection at load is a `TryFrom<String>` on the enum so TOML, env and API all
  produce the same message; `FromStr` stays the env path.
- Bench IDs of the adaptive arms are unchanged (`_adaptive` suffix kept) so
  criterion history stays comparable; only the `fallback` arms are gone.
- `penalty_failures` stays at 2 — S1-G4 derived nothing (three length-1 runs).
