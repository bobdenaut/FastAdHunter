# p2.6-08 — Microbench S1-M (G2 tier 1)

## Implementation Summary

- New criterion bench `crates/fah-dns/benches/upstream_select.rs`
  (`harness = false`): M.1–M.7 plus the `select/noop` control, over a synthetic
  `Vec<Health>`. No sockets, no runtime, no clock — `now` returns a constant.
- `tests/forward_alloc.rs` gained one `println!` for the M.9 counts; the
  assertion is unchanged.
- No bench-only constructor needed: `PackedWord::store` is already
  `#[doc(hidden)] pub` and `pack`/`State` are public.
- M.1/M.2/M.5/`noop` run behind `#[inline(never)]` wrappers — equal call
  overhead on both sides, and a symbol to disassemble. M.7 uses four
  long-lived threads and two `Barrier`s, with a `claim_probe_harness_only`
  arm subtracting the harness.
- Assertions outside the timed loops: clock evaluated 0× for M.1/M.2, exactly
  1× for M.3/M.4; M.5 stores nothing; M.6 crosses the threshold. M.7 asserts
  one `Probe` per batch **inside** the loop — every batch checked.
- Gates: `fmt --check`, `clippy --workspace --all-targets -D warnings`,
  `test --all-features --workspace` — green.

## Decisions

- **M.9 reports from the existing test, not a second bench binary.** A
  `#[global_allocator]` is per-binary: one inside `upstream_select` would
  perturb the ns arms, and a separate binary would duplicate
  `forward_alloc.rs` wholesale (principle 4).
- **Two A/B controls**: `upstream/forward_udp_answered` (fallback) and the
  CPU-bound `fah-rules/benches/decisive`. The forward arm's run-to-run band is
  ±9 %, too wide to certify a session at ±2 % on its own.
- **M.7 reported unpinned as well as pinned to four cores.** Pinned, a round
  costs ~28 µs against ~1.7 µs unpinned: 5 runnable threads (4 racers + the
  resetting main) on 4 cores serialize — the PERFORMANCE.md "pinning is for
  CPU-bound microbenches only" trap. Neither pin resolves the claim above the
  barrier cost; the criterion that matters is asserted, not timed.
- **M.1's structural claim is an instruction count**, from
  `cargo rustc --bench upstream_select --profile bench -- --emit asm`.
- **M.8's rule was corrected before classification, not after.** The original
  tested criterion's within-run CI against an arm whose variance is
  between-run, and rejects identical code (null baseline: 1 of 6 to 5 of 15
  overlaps). The replacement uses a paired between-run t-CI and enforces the
  10 % blocker twice. Owner-approved; no tolerance added, nothing discarded.

### M.1 — instruction count (the "one relaxed load, early exit" claim)

Taken path of `select_claim` (2 endpoints, first Healthy) in
`target/release/deps/upstream_select-*.s`:

| Segment | Instructions | Memory traffic |
| --- | --- | --- |
| Prologue (8 × `pushq`, `subq`) | 9 | 8 stack stores |
| `testq`/`je` slice-empty guard | 2 | — |
| **`movq (%rcx), %r8`** | **1** | **one relaxed load of the state word** |
| State decode + early-exit branch | 12 | none |
| Result materialisation + epilogue | 16 | 8 stack loads |
| **Total** | **40** | one load of `Health.state` |

`select/noop`: 8 instructions, one load. Of the 32-instruction delta, 22 are
`#[inline(never)]` prologue/epilogue and 10 are real decode. On the healthy
path: **no `lock` prefix, no store, no call, no second load** — the scan loop
at `.LBB46_11` is never entered, the clock closure never materialised
(asserted separately: 0 evaluations).

The control arm's workers **skip `select` entirely**; only the reset and the
two barriers run. The difference therefore covers **the whole `select` call on
a one-endpoint slice — scan, unpack, deadline compare and CAS — not the CAS in
isolation.** No figure here is an isolated CAS cost, and none may be re-quoted
as one.

- Winner count **exactly 1** on every batch of every run (asserted in the timed
  loop; ~250 k batches per unpinned run).
- `claim_probe` − `claim_probe_harness_only`, unpinned: 0.157, 0.130, 0.046 µs
  for 4 concurrent `select` calls → **≤ ~40 ns per contended claim, `select`
  included**. It does not grow with repetition: no spin.
- Pinned to four cores the two arms are indistinguishable — the barrier round
  trip dominates by ~4 orders of magnitude.

## Findings

| # | Severity | Finding | Disposition |
| --- | --- | --- | --- |
| F1 | Major | M.8's K was not pre-declared — extended 3 → 6 mid-session | **DEFERRED** — cannot be made retrospective |
| F2 | Minor | Session-validity control is not a pure null | **FIXED** — pure null control added; `decisive` demoted to descriptive |
| F3 | Minor | M.1's 1.7 ns is an upper bound, not the production cost | **DOCUMENTED** — M.1–M.4 not redesigned |
| F4 | Minor | M.1–M.4 measure an L1-resident, perfectly-predicted word | **DOCUMENTED** — M.1–M.4 not redesigned |
| F5 | Minor | Bench `POLICY` duplicates the shipped policy constants | **FIXED** — derived from `Policy::from_timeout` |
| F6 | Minor | M.7's control subtracts all of `select`, not only the CAS | **FIXED** — arm renamed, wording corrected |
| F7 | Nitpick | M.9 print visibility; `#[doc(hidden)]` dependency; M.2 duplicates M.1's path | **FIXED / ACCEPTED** |

**F1 — K not pre-declared.** *Rationale:* optional stopping biases clause 1 if
the decision to extend depends on the observed deltas. *Evidence against bias:*
no acceptance rule existed when the extension was made — the rule was authored
after; all 12 runs are reported, none discarded; the **worst** pair for
`adaptive` (+3.08 %) is pair 6, the last one, so the session did not stop on a
favourable result. *Impact:* clause 1 is not a pre-registered test here.
Clauses 2 and 3 are per-pair/bound tests and are immune to stopping rules, so
the 10 % blocker is unaffected. *Fix:* the next M.8 execution (`p2.6-11`)
pre-declares K in the results file. Re-running now to satisfy a
pre-declaration that did not exist would be re-running for an outcome, which
the corrected rule forbids. **Measured, not inferred.**

**F2 — control not a pure null.** `fah-rules/benches/decisive` links
`fah-model`, which changed between the two checkouts (`engine.rs`, `lib.rs`,
`perf.rs`; +137/−4), so the ±2 % session-validity claim carries a
code-placement confound (PERFORMANCE.md: one never-called `pub fn` moved a
`fah-rules` arm +7.9 %). `lookup_only` at +2.01 % sits on the boundary.
*Counter-evidence:* the two tightest arms (`id_of/*`, CI < 0.3 %) read
−0.20 %/−0.33 %, so the box itself was stable.
**Inference from the diff, plus measured arm behaviour.**
*Fixed:* no existing bench qualified — `fah-dns`, `fah-http`, `fah-rules`,
`fah-metrics`, `fah-stats` and `fastadhunter` all reach `fah-model`, and
`fah-metrics`/`fah-stats`/`fah-api`/`fastadhunter` changed themselves. Added
`fah-common/benches/session_control` (host crate has no path dependencies; the
bench uses no item from it), so no project change can move it. This session's
`decisive` numbers are **kept as descriptive evidence** — the new control did
not exist at `786e8c8` and cannot be applied retrospectively.

**F3 — M.1 is an upper bound.** `select_claim` is `#[inline(never)]`: 22 of its
40 instructions are prologue/epilogue for callee-saved registers the
never-entered scan loop needs. In `forward`, `select` is inlined and pays none;
`select_noop` saves no callee-saved registers, so the +1.05 ns delta is
inflated on the measured side. Conservative direction — read "≤ 1.7 ns".

**F4 — ideal cache and branch state.** The `Vec<Health>` is hammered for
seconds per arm: the word is L1-resident, the early-exit branch perfectly
predicted. Production reads it once per query (~0.68 QPS on the RB5009) off a
likely-cold line: ~80 ns x86 / ~700 ns RB5009-equivalent. `fallback` holds no
per-endpoint state, so that miss is **added** by Stage 1 and is **not** what
M.1 measures. At 0.03 % of an ~81 µs `forward` it changes no verdict, but it
bounds what M.1 proves; `p2.6-11`'s live run is where it would show.
**Inference — the miss cost is not measured here.**

**F5 — duplicated policy constants.** The bench hardcoded
`penalty_base_ms: 24_000` / `penalty_max_ms: 300_000`; if `PENALTY_BASE_FACTOR`
or `PENALTY_MAX_MS` changed, it would silently measure a policy production no
longer uses. *Fixed:* `Policy::from_timeout` is now a `const fn`
(`u64::from(ATTEMPT_LEGS)` → `ATTEMPT_LEGS as u64`, the only non-const step),
and the bench derives `const POLICY: Policy = Policy::from_timeout(800, 3);`.
`800` is the shipped `dns.upstreams.timeout_ms` default and stays an explicit
input; `penalty_failures = 3` remains the bench's own parameter. The derived
values are byte-identical to the removed literals, so the workload and every
acceptance computation are unchanged — no re-measurement.

**F6 — M.7 control scope.** The control's workers skip `select` entirely, so
the difference covers scan + unpack + deadline compare + CAS on a one-endpoint
slice — never the CAS alone. *Fixed:* arm renamed
`claim_probe_barrier_only` → `claim_probe_harness_only` (the raw logs of this
session carry the old label), and the M.7 section now states the scope
explicitly and forbids re-quoting the figure as CAS cost. Workload unchanged —
the control arm's workers did nothing before the rename and do nothing after.

**F7 — nitpicks.** *Fixed:* the exact command for the M.9 figure is now in the
M.9 section (`cargo test -p fah-dns --release --test forward_alloc --
--nocapture`; the assertion itself always runs). *Accepted, no change:* the
bench consumes `PackedWord::store` (`#[doc(hidden)] pub`), which therefore
cannot be deleted — no new bench-only entry point was added, and the
alternative is a second one. M.2 exercises M.1's path (1.746 vs 1.732 ns); its
value is confirming length-independence, so it stays. A failed assertion in
`b.iter` parks the four racers on `start.wait()`, but the panic unwinds out of
`main` and the process exits — no hang, and a `Drop`-based release would add
state for a failure mode that cannot hang.

**No bugs found in the measured code.** F1–F2 are measurement methodology,
F3–F7 bench scope and hygiene; nothing in `fah-dns` is implicated.
