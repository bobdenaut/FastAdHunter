# P1.5-06 — Verification (history end-to-end + on-device soak)

**Phase:** 1.5 · **Depends on:** p1.5-01..p1.5-06 · **Model:** Opus

## Goal

Prove the observability base end-to-end: rollups and perf samples are written,
pruned, and served correctly, and the whole thing stays disk- and
memory-bounded on the RB5009 under load.

## Context

Phase 1 closed on the strength of an on-device soak (docs/code-review/
p1-11-soak.md) driven by `test_aleator.py` (kept from phase1's soak, under
`plan/closed/phase1/` — 50 workers, 7 query types, v4+v6). Reuse it. Unit
tests live in each task; this task adds the cross-cutting e2e + the device run.

## Scope

- **Workspace tests** (`cargo test --workspace`) consolidated green: rollup
  arithmetic, retention pruning in tempdirs, perf-sample round-trip, config
  live-apply, byte-cap enforcement.
- **e2e** (`crates/fastadhunter/tests/` or `tests/`): boot the stack, drive
  queries, advance the clock past an hour boundary, assert a rollup file
  appears and `GET /api/v1/history/summary` returns it; assert
  `GET /api/v1/history/perf` carries non-zero `rss_bytes` + cache stats; assert
  `GET /api/v1/history/top` returns seeded top-N; flip `retention_days` via
  `POST /api/v1/config` and assert the next prune honors it.
- **On-device soak:** run `test_aleator.py` against the RB5009 build; over a
  representative window confirm `/data/history/` stays within `retention_days`,
  total disk usage is bounded, process RSS is unchanged by the sampler (hard
  rule #4), and the cache byte cap holds under the worst-case mix.
- Record results in `docs/code-review/phase1/p1.5-07-review.md` (mirror the
  p1-11-soak.md format).

## Acceptance criteria

- All workspace gates green; e2e passes.
- On-device: history disk bounded, RSS flat with the sampler on, cache within
  the byte cap under the hammer.
- Verification doc written with real device figures.
- Phase 1.5 DoD (see phase CLAUDE.md) satisfied.

## Out of scope

The dashboard UI; any new feature — this task only verifies.
