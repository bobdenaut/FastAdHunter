# P1.5-01 — History Rollup Store (hourly → daily aggregates)

**Phase:** 1.5 · **Depends on:** phase1 (`fah-stats`) · **Model:** Sonnet

## Goal

Long-term, bounded aggregate time-series on `/data` so a dashboard can chart
query volume, block rate, query types, and daily top-N over 30/60/90 days —
without scanning the raw query log.

## Context

`fah-stats` already owns `/data` persistence. The aggregate time-series today
is a bounded **24-hour ring** (`crates/fah-stats/src/bucket.rs`,
`HourlyBuckets`, 24 slots keyed by hour-of-epoch) — it *cannot* hold history:
a slot is overwritten 24h later. This task captures each completed hour before
it rolls off, into append-only per-day JSONL. Reuse the append+prune pattern
from `crates/fah-stats/src/query_log/segment.rs` (`SegmentWriter`) and the
atomic-write pattern from `snapshot.rs`.

## Scope

- New POD types in **`fah-model`** (data + `Serialize`/`Deserialize` only —
  hard rule #2): `HourRollup { hour_epoch, queries, blocked, cache_hits,
  per_type: BTreeMap<QueryType,u64> }`, `DailyTopN { day_epoch, top_blocked,
  top_queried, top_clients }` (reuse `DomainCount`/`ClientCount` shapes).
- New module `crates/fah-stats/src/history/rollup.rs`:
  - At each hour boundary (detected when `HourlyBuckets` advances past a slot's
    `hour_epoch`), append the completed `HourRollup` to
    `/data/history/rollups/rollup-YYYY-MM-DD.jsonl` (one file/day, ≤24 lines).
  - Maintain a **daily top-N accumulator** (mirrors `top_n.rs`) that resets at
    day boundary and is flushed as one `DailyTopN` line into the same day file
    (or a sibling `top-YYYY-MM-DD.json`).
  - `boot()` resumes cleanly (idempotent — re-appending the same hour must not
    double-count; key by `hour_epoch`).
  - `prune(retention_days)` deletes whole day-files older than the cap; never
    the current day. (`retention_max_mb` optional here — rollups are tiny.)
- Per-type counts require the hourly bucket to also track per-`QueryType`
  totals — extend `Slot` in `bucket.rs` (still fixed-size, hard rule #4 holds).
- Wire into `Stats`: a scheduler tick (reuse the snapshot/flush scheduler
  cadence) checks for a completed hour/day and writes rollups.

## Acceptance criteria

- Driving queries across a simulated hour boundary produces exactly one
  `HourRollup` for the completed hour with correct sums and per-type counts.
- A day boundary produces one `DailyTopN`.
- `prune` removes day-files past `retention_days`, keeps the active day.
- Rollup memory is fixed regardless of query volume/uptime.
- Gates green.

## Out of scope

The perf/RSS/cache sample series (p1.5-02); the read API (p1.5-04); retention
made REST-settable (p1.5-03 — this task takes `retention_days` as a value).
