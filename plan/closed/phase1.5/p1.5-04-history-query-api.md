# P1.5-04 — History Query API (chart-ready series)

**Phase:** 1.5 · **Depends on:** p1.5-01, p1.5-02 · **Model:** Sonnet

## Goal

Read endpoints that serve the persisted history as chart-ready JSON, so the
future dashboard fetches ranges instead of parsing raw files.

## Context

`fah-api` already exposes the live `GET /api/v1/stats`, `/queries`, `/cache`.
These new endpoints read the `/data/history/` JSONL the writers produce
(p1.5-01/02) via the `fah-stats` handle (siblings wire through the binary).
Reads are range-scoped and bounded (never load 90 days into memory
unfiltered — stream/aggregate day-files within the requested range).

## Scope

- `GET /api/v1/history/summary?from=&to=&resolution=hour|day` → time-series of
  `{ ts, queries, blocked, blocked_percent, cache_hits, per_type }` from the
  rollups (day resolution aggregates the 24 hourly rows).
- `GET /api/v1/history/perf?from=&to=&fields=` → the `PerfSample` series
  (RSS, latency percentiles, cache stats, upstream health); optional `fields`
  filter to keep payloads small; may down-sample very wide ranges.
- `GET /api/v1/history/top?from=&to=&kind=blocked|queried|clients&n=` → top-N
  over the range, merged from the `DailyTopN` records.
- API.md: document the three endpoints (auth-required, response shapes,
  range/paging limits) beside the other stats endpoints.
- Consistent error handling: bad range → `400`; empty range → `200` with empty
  series (not `404`).

## Acceptance criteria

- Seeding `/data/history/` fixtures and calling each endpoint returns the
  expected aggregated series (hour and day resolution both correct).
- A range with no data returns an empty series, `200`.
- Response size stays bounded for a 90-day range (down-sampled/paged).
- API.md matches the implementation (shapes, params, auth).
- Gates green.

## Out of scope

The dashboard UI (later phase); WebSocket streaming of history (the live
`WS /api/v1/events` already covers real-time).
