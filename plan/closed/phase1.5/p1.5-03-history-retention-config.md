# P1.5-03 — History Config + REST-Live Retention

**Phase:** 1.5 · **Depends on:** p1.5-01, p1.5-02 · **Model:** Sonnet

## Goal

A `[history]` config section, and a `retention_days` the user can change to
30/60/90 (or anything) **via REST without a restart**, applied live to both
history writers.

## Context

`GET /api/v1/config` / `POST /api/v1/config` (API.md:283–287) already
read/rewrite config; `retention_days` is a "runtime"-class field, so live-apply
should reuse that path rather than invent a new one. Note the p1-07 review
caveat: the query-log retention is currently *baked at construction*
(`Stats::new` copies `retention_days` into a plain field). The history writers
must instead hold retention behind an atomic so a config apply takes effect on
the next prune without reconstructing anything (hard rule #3: config changes via
atomic swap, not locks on the hot path).

## Scope

- `crates/fah-config`: new `HistoryConfig { enabled: bool,
  sample_interval_seconds: u32, retention_days: u32 }` with documented defaults
  (`enabled = true`, `sample_interval_seconds = 60`, `retention_days = 30`).
  Env override `FAH__HISTORY__…` like the rest.
- History writers (rollup + perf) hold `retention_days` as an
  `AtomicU32`/`ArcSwap`; a setter updates it; `POST /api/v1/config` calls the
  setter when the value changes. `sample_interval` change may take effect on
  the next tick (document whether it needs a restart — prefer live).
- CONFIGURATION.md: document `[history]` next to `[stats]`/`[query_log]`,
  including the class (boot vs runtime) of each field and the 1 TB-SSD
  rationale for defaults.
- SECURITY.md: note that history extends the retained-data window (privacy);
  `enabled = false` disables it, mirroring `query_log.enabled`.

## Acceptance criteria

- Setting `history.retention_days` via `POST /api/v1/config` changes what the
  next prune keeps — no restart, verified in a test.
- Defaults documented and loaded; env override works.
- Invalid values (`0`, absurd) rejected/clamped consistently with existing
  config validation.
- Gates green.

## Out of scope

The writers themselves (p1.5-01/02); the read API (p1.5-04).
