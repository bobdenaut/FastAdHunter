# Plan — p2.5-06 Failure Run-Length Instrumentation

## Summary

Per-endpoint closed-run failure buckets (lengths 1, 2, 3, ≥ 4) exported
via `/telemetry` and, automatically, the persisted perf series — the
S1-G4 data source. Ship early; the phase CLAUDE.md's mid-phase deploy
lands here.

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Run definition | maximal sequence of consecutive transport failures on one endpoint, closed by that endpoint's next transport success; RCODEs are successes (pinned by p2.5-04 U3) |
| Capture point | success arm of `UpstreamPool::forward` (`crates/fah-dns/src/upstream/mod.rs:188`): `consecutive_failures.store(0)` becomes `swap(0, Relaxed)`; nonzero previous value = closed run |
| Storage | `run_buckets: [AtomicU64; 4]` on `UpstreamServer` (mod.rs:229-236) |
| Bucketing | `fn run_bucket(len: u64) -> usize`: 1→0, 2→1, 3→2, ≥4→3; `pub(crate)`, in mod.rs |
| Open runs | not bucketed until closed (visible meanwhile as `consecutive_failures`); a run open at process exit is lost — accepted and documented |
| Export shape | `failure_runs: [u64; 4]` added to `UpstreamStatus` (mod.rs:56-71), to `fah_model::UpstreamSample` with `#[serde(default)]`, copied by `status()` and the telemetry poll (`crates/fastadhunter/src/main.rs:604-617`), passed through `fah-metrics` `set_upstreams` untouched |
| Persistence | accepted explicitly: `UpstreamSample` is embedded in the persisted perf series (`crates/fah-model/src/perf.rs:39`), so the field rides `/history/perf` — 32 bytes × N endpoints per 60 s sample against a ~740 B/sample baseline |
| Bucket boundaries | fixed constants; not configurable |

## Implementation units

**U1 — buckets + capture.** Field, `run_bucket`, and the
`swap`-then-bucket in the success arm. The failure arm is untouched; the
happy-path delta is exactly `store` → `swap` (same atomic RMW class) plus
a branch on a register value that is zero on every healthy query.

**U2 — export chain.** `UpstreamStatus.failure_runs` → `status()` copy →
`UpstreamSample.failure_runs` (serde-defaulted) → telemetry poll copy →
`/telemetry` upstream array. No fah-api change (it serves the fah-model
type).

**U3 — window start.** Review file dates the S1-G4 observation window at
the owner's deploy of this build.

## Invariants (must hold before and after)

- Buckets are monotonic non-decreasing per endpoint.
- Σ over an interval: closed runs of length L consume exactly L failures —
  cross-checkable against the `failures` counter delta (assert in tests).
- No cross-endpoint contamination.
- Old persisted `PerfSample` rows (no `failure_runs`) deserialize with
  zeroed buckets.
- Happy-path additions: the swap + one zero-check, nothing else.

## Tests (all objectively checkable)

1. Sequences on a mock transport, per endpoint: F,S → [1,0,0,0];
   F,F,S → [0,1,0,0]; F,F,F,S → [0,0,1,0]; F×5,S → [0,0,0,1]; S-only →
   [0,0,0,0].
2. Interleaved: primary F,F while secondary S,S; then primary S →
   primary [0,1,0,0], secondary [0,0,0,0].
3. RCODE closes a run: seeded `consecutive_failures == 2`, next response
   SERVFAIL → buckets gain [0,1,0,0] (composes with p2.5-04's pinning).
4. Serde: `UpstreamSample` JSON without `failure_runs` → zeroed array.
5. Monotonicity across two consecutive `status()` calls under load.

## Out of scope (closed paths)

- No interpretation of the distribution (S1-G4 gate does that later); no
  penalties, probes, or walk changes.
- No open-run flushing at shutdown; no persistence beyond the automatic
  perf-series ride; no config keys.
- No per-caller (SWR vs client vs resolve_host) split of the buckets —
  transport failures are endpoint properties (spec S1.8 handles caller
  isolation separately, in Stage 1).
