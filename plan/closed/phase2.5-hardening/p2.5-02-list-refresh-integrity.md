# P2.5-02 — List Refresh Integrity

**Phase:** 2.5 · **Depends on:** — · **Model:** Opus

## Goal

A fetched list body that parses to garbage can no longer replace the
last-good `/data` copy or the served ruleset, and parse failures are visible
through the API.

## Context

Reconciled §5.2 / GAR-A risk 2: `fetch_and_commit` commits any fetched body
to the `/data` cache before any content check
(`crates/fah-rules/src/lifecycle/mod.rs:637-654`) — by design, "the only
failure mode is I/O, never parsing". A CDN error page, captive portal, or
truncated file arriving as HTTP 200 destroys the last-good copy and swaps a
near-empty ruleset in. `looks_misparsed` (`mod.rs:135`) only warns, and
`parse_errors` reaches no API surface (project-state.md records this gap).
Network-triggered, silent, and repeated at every refresh interval.

## Scope

- Validate the fetched body **before** `commit_raw`: parse it (a second full
  parse, on the blocking pool) and refuse the commit when the content fails
  the gate — an HTML document (`<!doctype` / `<html` leading the body);
  `looks_misparsed` firing; or, only while the serving copy has
  DNS rules, a body with zero DNS rules, or a DNS + URL rule count under a
  tenth of a serving copy of 1000 or more rules. A refused body behaves
  exactly like an I/O failure: last-good copy untouched, no compile,
  `RefreshResult::Rejected(reason)` recorded.
- The gate must not reject legitimate shrinkage (lists do shrink); thresholds
  err on the side of accepting, with the misparse heuristic as the hard
  signal. A source that legitimately restructures below the lines stays
  rejected across restarts; **the recovery contract is `DELETE` + re-add**
  (no baseline on a first fetch), pinned by test.
- Expose `parse_errors` (serving copy) and the rejection reason
  (`last_error`) per list through the existing `/api/v1/lists` status
  payload; `rejected` is one status word on `last_status`, on
  `POST /api/v1/lists/refresh` results and on the `list_refreshed` event. No
  new endpoint, no query-log or Prometheus revival (p2-09 stands).
- I/O-failure semantics, refresh scheduling, and the compile path stay
  unchanged.

## Acceptance criteria

- Test: HTTP 200 with an HTML/empty/binary body → `/data` copy untouched,
  previous ruleset keeps serving, list status shows the failure and reason.
- Test: a legitimately updated list still commits and compiles.
- `parse_errors` visible via the lists API; API.md and RULE_ENGINE.md updated
  in the same change (owner-approved 2026-08-22).
- Test: `DELETE` + re-add clears a rejected baseline.
- Gates green.

## Out of scope

Bounding `pending_cache` in aggregate and Content-Length pre-checks (both
recorded as phase2 follow-ups, still untasked); signature/checksum
verification of list sources.
