# Plan — p2.5-07 SWR Claim Lease vs Worst-Case Upstream Walk

## Summary

The refresh claim lease is a constructor parameter the **binary** derives
from the upstream config — the cache keeps its refusal to know upstream
configuration — and the lease exceeds the worst-case walk **by
construction**: every server attempt carries an outer wall-clock bound of
`3T` at the `UpstreamPool` layer, so the walk is `≤ 3 × N × T` regardless
of what the transport does inside.

## Why the amendment

The original plan derived `3NT` from the timed legs inside
`ExchangeConn::query` (send ≤ T, reconnect ≤ T, retry send ≤ T). Two legs
are untimed: the `slot` mutex wait in `ExchangeConn::acquire`
(`encrypted.rs:123`) and in `invalidate_if_current` (`encrypted.rs:143`).
The lock is held across `connect`; with the pooled exchange `None` and a
dead server, every waiter runs its own connect in turn, so the *k*-th
concurrent forward waits `k × T` before its own legs start. *k* is the
number of in-flight misses plus SWR workers — nothing bounds it. `3NT` was
therefore a bound on timed legs, not on wall-clock, and "provably exceeds"
was not met. Known since p2.5-03 F2 (deferred to Stage 1 S1.6/S1.7); this
task's original closed path "no change to how the walk is timed" was wrong
to inherit that deferral while claiming a proof.

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Per-server attempt bound | **Outer** `tokio::time::timeout(ATTEMPT_LEGS × T, …)` around the transport call in `Server::query` (`upstream/mod.rs:363`), one site covering UDP and encrypted. `pub const ATTEMPT_LEGS: u32 = 3` lives next to it in `upstream/mod.rs` and is the only place the leg count is written |
| Why 3 | Inner legs: encrypted pooled path = send ≤ T + reconnect ≤ T + retry send ≤ T; plain UDP = udp ≤ T + TC→TCP ≤ T. The outer bound is ≥ the sum of inner bounds, so it never fires before an inner timeout on an uncontended attempt; it fires only when an untimed leg (mutex wait) consumed the budget |
| Outer-timeout error | `io::ErrorKind::TimedOut`, message distinguishes it from the inner ones ("upstream attempt exceeded its wall-clock bound"). Same classification p2.5-04 gives inner timeouts, so `consecutive_failures`, run buckets, alarm and fallback-to-next-server behave identically |
| Walk bound | `worst_case_walk = ATTEMPT_LEGS × N × T`, exported as `pub fn fah_dns::worst_case_walk(upstreams: &fah_config::DnsUpstreamsConfig) -> Duration` in `upstream/mod.rs` — the bound lives next to the code that enforces it (closes review #7) |
| Lease formula | `lease = max(5 s, 2 × worst_case_walk)`; N = `servers.len()`, T = `timeout_ms`. Unchanged numbers: (2, 800) → 9.6 s; (8, 800) → 38.4 s; (1, 100) → 5 s |
| Why 2×, still | Executor scheduling latency and `yield_now` are not timer-bounded; 2× is the margin for that and for the claim-to-dequeue gap (see "Out of scope"). It is no longer carrying the mutex wait |
| No lease ceiling | Review #5 closed as invalid. `suppress_refresh` assigning `now + 30 s` after a failed walk does not damage a longer claim — the claim's purpose ends when the walk ends, the cooldown then governs. The lease<cooldown ordering in `a_failed_refresh_suppresses…` is test scaffolding, not an invariant. A ceiling would break "lease ≥ 2 × walk for every constructible config", which is the whole task |
| Parameter path | Unchanged from the shipped implementation: `DnsCache::new(config, refresh_claim_lease)`, `Pipeline::new(rules, forwarder, blocking_ttl, cache_config, refresh_claim_lease, events)` |
| Default for tests/benches | Unchanged: `pub const DEFAULT_REFRESH_CLAIM_LEASE = 5 s` from `fah-dns` |
| Config validation | None (unchanged; `deny_unknown_fields` migration-trap class) |
| p2.5-03 invariant preserved | Inner `send_once` timeout still invalidates the pooled exchange. The outer timeout does **not** invalidate: it can only fire after an untimed wait consumed budget, and the exchange is not known bad. If it interrupts a `send_once`, the next query's own inner timeout invalidates within T |

## Implementation units

**U1 — parameterize.** Done in the current tree (field, constructor,
`DEFAULT_REFRESH_CLAIM_LEASE`, const deleted, call-site sweep). No change.

**U2 — outer attempt bound.** `crates/fah-dns/src/upstream/mod.rs`:

- `pub const ATTEMPT_LEGS: u32 = 3;`
- `Server::query` becomes `timeout(attempt_timeout * ATTEMPT_LEGS, <existing match>)`, mapping `Elapsed` to `io::Error::new(TimedOut, …)`.
- `pub fn worst_case_walk(upstreams: &DnsUpstreamsConfig) -> Duration` = `Duration::from_millis(u64::from(timeout_ms)) * ATTEMPT_LEGS * servers.len()`; re-exported from `lib.rs` alongside `UpstreamPool`.
- `UpstreamPool::forward` loop, error handling, fallback order, counters, alarm: untouched.

Cancel-safety of the outer timeout, by leg: during the `slot` lock wait
nothing is held; during `connect` the guard drops (lock released, slot
stays `None`, `handshakes` already counted — an attempt was made); during
`send_once` hickory drops the in-flight request's oneshot. UDP: socket
dropped. DoH `lookup_host` is on a blocking thread and finishes on its own
(pre-existing, timed).

**U3 — derivation uses the exported bound.** `crates/fastadhunter/src/main.rs`:
`refresh_claim_lease(upstreams)` = `(fah_dns::worst_case_walk(upstreams) * 2).max(Duration::from_secs(5))`.
The literal `6 *` goes away.

**U4 — docs.** Review file S1.9 table and proof section restated for the
wall-clock bound (done with this amendment, see "Documentation changes").
ADR-0005 §lease paragraph rewritten (done with this amendment).

## Invariants (must hold before and after)

- One server attempt ≤ `ATTEMPT_LEGS × T` wall-clock, for UDP, DoT and DoH,
  under any number of concurrent forwards to that server.
- One `forward` walk ≤ `ATTEMPT_LEGS × N × T` wall-clock.
- Lease ≥ 2 × walk for every constructible config, and ≥ 5 s always.
- Uncontended attempts are unaffected: the outer bound ≥ sum of inner
  bounds, so observed latency, error kinds and retry behaviour are identical
  when no untimed wait occurs.
- Fallback ordering (sequential, every server tried, last error returned),
  `io::ErrorKind` fidelity (p2.5-04), pooled-exchange invalidation on inner
  timeout (p2.5-03), `consecutive_failures`/run buckets (p2.5-06), alarm:
  unchanged.
- `REFRESH_FAILURE_COOLDOWN` (30 s), `STALE_SERVE_TTL`, `MAX_STALE`, SWR
  worker count, queue depth (64/worker), drop-not-backpressure, claim
  release on drop (ADR-0005): unchanged.
- Hot path: nothing on a fresh hit or a blocked query changes. Miss path
  gains one `tokio::time::Sleep` registration per server attempt, stack
  only, no heap.

## Tests (all objectively checkable)

1. **Attempt bound, encrypted.** `upstream/mod.rs` tests, `start_paused`:
   a `Server` with an `Encrypted` transport whose `slot` is held by the test
   (`#[cfg(test)] pub(super) async fn hold_slot(&self) -> MutexGuard<Slot>`
   on `ExchangeConn`). `server.query(…, T)` returns `Err` with
   `kind() == TimedOut` and `Instant::now() - start == T * ATTEMPT_LEGS`
   exactly (paused clock). Proves the lock wait is bounded and ties the
   constant to the behaviour.
2. **Walk bound, pool.** Same setup, N = 2 servers both held. `forward`
   returns `Err(TimedOut)` after exactly `2 × ATTEMPT_LEGS × T`; both
   servers show `attempts == 1`, `failures == 1` (fallback order and
   counters preserved under the outer bound).
3. **Outer bound never pre-empts an inner timeout.** UDP server that never
   answers (bound to a socket nobody reads), `forward` with T: error kind
   `TimedOut`, elapsed == T (inner udp timeout fired, not the outer 3T).
   Pins "uncontended attempts unaffected".
4. **Derivation.** `worst_case_walk` (2, 800) → 4.8 s; lease (2, 800) →
   9.6 s, (8, 800) → 38.4 s, (1, 100) → 5 s, (0, 800) → 5 s. Replaces the
   current main.rs test's arithmetic with calls through the exported fn.
5. **Existing suites** green: SWR/claim/cooldown, p2.5-03 reconnect, p2.5-04
   error kinds, p2.5-06 run buckets.
6. **Non-blocking (review #1), recommended.** Pipeline test: forwarder test
   double that stalls 8 s, `Pipeline::new(…, lease = 10 s, …)`, stale entry,
   three stale hits during the stall → exactly one `forward` call; a fourth
   hit after the lease lapses with the stall still running → a second call.
   Pins that the lease is stamped where the walk starts and consumed by the
   pipeline, not only by the cache.

Not added, by decision: any test that only advances a paused clock against
`cache_with_stale_entry(<derived lease>)` — it restates test 4 ∘ the
existing 50 ms field test and observes no walk.

## Out of scope (closed paths)

- SWR queue contract: no re-stamp at dequeue, no worker or queue changes,
  no per-entry lease, no config key for the lease.
- No lease ceiling; no config validation; no 8-endpoint cap (Stage 1).
- No change to inner transport timeouts, reconnect or retry semantics, or
  to serialisation of connects behind `slot` (Stage 1 S1.6/S1.7 — the
  outer bound caps the damage, it does not remove the queueing).
- No outer timeout on the whole `forward` walk — per-server is what makes
  N × bound a proof without a second constant.

## Acceptance criteria

1. `Server::query` wall-clock ≤ `ATTEMPT_LEGS × T` with the slot held (test 1).
2. `forward` wall-clock ≤ `ATTEMPT_LEGS × N × T` with every slot held (test 2).
3. Uncontended timeout behaviour unchanged (test 3; p2.5-03/04 suites green).
4. Lease = `max(5 s, 2 × worst_case_walk)` from the exported fn (test 4).
5. ADR-0005 and the review file state the wall-clock guarantee; no document
   still calls `3NT` a timed-leg bound or names `REFRESH_CLAIM_LEASE`.
6. Gates green. Existing benches drive a mock forwarder and cannot observe
   `Server::query`; a focused `fah-dns` bench `upstream` (answered loopback
   UDP forward; fast UDP failure via ICMP unreachable) is A/B'd interleaved
   against a `3e36fd0` worktree carrying the same bench source. Delta on
   the answered path inside the box's control band.
