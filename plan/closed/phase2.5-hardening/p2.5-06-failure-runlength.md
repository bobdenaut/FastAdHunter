# P2.5-06 — Failure Run-Length Instrumentation

**Phase:** 2.5 · **Depends on:** p2.5-05 · **Model:** Opus

## Goal

The per-endpoint failure run-length distribution — the measurement gate
S1-G4 depends on and the current build cannot report — becomes observable
on-device, so the observation window starts now rather than when Stage 1
is otherwise ready.

## Context

The accepted spec names this the blocking open measurement
(`docs/design/adaptive-upstream-selection.md` §Failure clustering, lines
106-132): whether failures arrive as isolated losses or runs of ≥ 2 decides
whether `penalty_failures = 2` ever fires. The companion doc
(`docs/design/adaptive-upstream-selection-benchmarks.md`) carries the
measurement method. Both GAR reviews independently flagged the gap; the
Reconciled review lists it as ship-gate §5.3 for Stage 1.

## Scope

- Track, per endpoint, the distribution of consecutive-transport-failure
  run lengths: bounded counters (runs of length 1, 2, 3, ≥ 4 is enough for
  S1-G4's question). Increments happen on the failure/recovery path only —
  zero cost on the happy path, atomics in the existing per-server pattern.
- Export via `/telemetry` alongside the existing per-server counters; ride
  the perf-sample series only if the marginal bytes are trivial, else
  live-cumulative is sufficient (counters are monotonic; deltas across
  snapshots reconstruct the window).
- A run is closed by a transport success on that endpoint; RCODEs are
  successes (S1.4 semantics, pinned in p2.5-04).
- **Deploy note:** this task is why a mid-phase release is recommended —
  every deployed day before Stage 1 is S1-G4 data. The analysis itself (is
  `penalty_failures = 2` justified?) happens at the S1-G4 gate, not here.

## Acceptance criteria

- Unit tests: failure/success sequences produce the expected run-length
  buckets per endpoint; interleaved endpoints do not cross-contaminate.
- Counters visible in `/telemetry`; monotonic across snapshots.
- No hot-path cost (success path adds at most the existing counter writes).
- Gates green.

## Out of scope

Interpreting the distribution (S1-G4 gate); penalty logic; changes to the
`fallback` walk.
