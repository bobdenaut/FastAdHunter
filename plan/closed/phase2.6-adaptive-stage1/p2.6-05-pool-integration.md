# P2.6-05 — Pool Integration

**Phase:** 2.6 · **Depends on:** p2.6-01, p2.6-02, p2.6-03, p2.6-04 · **Model:** Opus

## Goal

`UpstreamPool::forward` runs Stage 1 when `strategy = "adaptive"`: select
(one pass, at most one probe per query), attempt, record, continue the scan
skipping Penalized endpoints. `resolve_host` runs in `Ignore` and never claims
a probe. SWR workers inherit the behaviour through `Forwarder`. The `fallback`
path is untouched and every existing upstream test passes with its assertions
unmodified.

## Context

Spec S1.2 (hot/cold split: `Arc<[Health]>` and the cold endpoint array),
S1.5, S1.7, S1.8 (`resolve_host` is ~20 % of attempts — isolation is
load-bearing), S1.9 (SWR is ~69 % — it records health and claims probes),
S1.11 (zero allocations, no locks, no timers), S1.14 (`fallback` is not
re-expressed as adaptive-with-penalties-off), S1.15 scenarios, S1.16
checklist, S1.17 (skip before connect; single-flight handshake kept).

## Scope

- Build `Policy` from config at pool construction: `penalty_base =
  10 × attempt_bound_ms` where `attempt_bound_ms = ATTEMPT_LEGS × timeout_ms`
  (24 s at the default), `penalty_max = 300 s`, `penalty_failures` from
  config (spec S1.6; `attempt_timeout` stays the per-leg value).
- Split `UpstreamServer` counters into the `Health` array; cold data stays
  where it is. `EndpointId` = config index.
- `forward` under `adaptive`: loop `select → attempt → classify → record`,
  `start = id + 1` on failure. A local `probed` flag and the mode feed the
  selector's `claim` (`claim = mode == Record && !probed`): at most one
  probe per query, and `Ignore` never claims. The clock is read lazily —
  never on the all-Healthy success path.
- `resolve_host` → `lookup` passes `HealthMode::Ignore`; selection still
  skips Penalized endpoints and never claims a probe.
- `fallback` branch: the existing code, byte-for-byte where possible.
- The `ExchangeConn` slot lock stays; penalizing never closes a connection.

## Acceptance criteria

- S1-G1 #4: every existing upstream test green under `fallback` with its
  assertions and behaviour unmodified (the `DnsUpstreamsConfig` literal
  field was added in `p2.6-01`; nothing else in those tests moves).
- S1-G1 #6 integration: all endpoints Penalized → a packet is still sent;
  a forced failure landing on the Penalized word leaves deadline and round
  unchanged.
- S1-G1 #7: `resolve_host` with one family black-holed moves no counter and
  no state.
- S1-G1 #8 integration: concurrent `forward` calls against a due endpoint →
  exactly one `Probing` claim — with a Healthy endpoint configured behind
  it, the others answer from the Healthy one; `tls_handshakes` of the dead
  endpoint unchanged after penalization.
- S1-G1 #14 end-to-end: idle-close → reconnect → answer under `adaptive`
  moves no counter and leaves `state` Healthy.
- S1-G1 #16: `resolve_host` against `[due, Healthy]` claims nothing.
- S1-G1 #17: `[due, due, Healthy]` with the first probe failing → one claim.
- S1.17 tests: N concurrent queries against `[penalized-dead, live]` all
  answer within one `attempt_bound_ms` of the live endpoint; N concurrent
  first queries against one live encrypted endpoint → exactly one handshake.
- Forward path adds no allocation, asserted the way the workspace already
  does it — an integration test with a counting `#[global_allocator]`
  (`crates/fah-rules/tests/url_lookup_alloc.rs` is the pattern), not a unit
  test inside `mod.rs`.
- `tests/layering.rs` unchanged and green. Gates green.
