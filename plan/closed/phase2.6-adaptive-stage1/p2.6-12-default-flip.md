# P2.6-12 — Default Flip

**Phase:** 2.6 · **Depends on:** p2.6-11 · **Model:** Opus

## Goal

`adaptive` becomes the compiled-in default, the `fallback` path is deleted
(principle 14), and every document that named the default says the new one.
A separate, explicitly approved commit; nothing here is implied by `p2.6-11`
passing.

## Context

Spec S1.14 (flip is a separate step gated on the deployment tier plus the
soak; `fallback` is deleted only after the flip). Root CLAUDE.md: docs are
the source of truth — a behaviour change updates the doc in the same change.

## Scope

- Default `strategy` → `adaptive`. `fallback` variant removed; a config that
  names it fails validation with a message saying it was removed in this
  release (deploy order stays binary first, config second).
- Delete the `fallback` branch in `forward` and the now-dead code it alone
  used. The existing upstream tests that S1-G1 #4 kept unmodified now run
  under `adaptive`; any that encoded ordered-walk-only behaviour are updated
  to the Stage 1 equivalent, with the change listed in the review file.
- `/health` degraded: the `fallback`-only rule goes.
- Docs, **each owner-approved at execution time**: CONFIGURATION.md
  `[dns.upstreams]` default; API.md if a value set changed;
  docs/project-state.md rewritten (never appended); the spec's status line
  marked "Stage 1 shipped as default" with the build.

## Acceptance criteria

- Every config in the repo and in the container boots on the new default.
- Gates green with the `fallback` code gone; `tests/layering.rs` unchanged.
- Review file lists every test changed and why.
- Commit waits for a fresh go; push goes to both remotes.

## Out of scope

Stage 2 or Stage 3 decisions — those are taken from the `p2.6-11` data in a
separate planning step, not in this task.
