## Implementation changes

1. New bench `crates/fah-dns/benches/upstream_select.rs`:
   - M.1 `select/2_healthy`, M.2 `select/8_healthy`,
     M.3 `select/8_first_7_penalized` (7 Penalized with future deadlines,
     8th Healthy — the one pass decodes 7 deadlines and evaluates the clock
     closure once), M.4 `select/8_all_penalized` (future deadlines; the
     forced scan), control `select/noop` (reads the same memory, returns 0).
     Every arm calls `select(.., claim = true)`; M.1/M.2 must not evaluate
     the closure (assert with a flag in a debug run, not in the timed loop).
   - M.5 `update/success` — `record(Success)` on a clean Healthy word (must
     be the early-return path).
   - M.6 `transition/penalize` — reset the word per iteration
     (`iter_batched`), then `record(HardFailure)` crossing the threshold.
   - M.7 `transition/claim_probe` — 4 `std::thread`s racing `select` on one
     due endpoint per batch; assert exactly one `Probe` per batch; report
     per-claim time. **Pinned to four cores, not one** (benchmarks §S1-M):
     four threads on one core serialize on the scheduler and the CAS is
     never contended. Run it as its own criterion group with its own pin.
   - The `now` closure returns a constant; no clock in the bench.
2. `fallback` equivalent for M.1: there is no selector in `fallback` — its
   "selection" is entering the transport. Use the existing
   `forward_udp_answered` arm on both strategies (p2.6-05) as the
   end-to-end comparison, and report M.1 against the `noop` control as the
   structural claim. M.8 is a **gross check** — syscall-dominated, tens of
   µs, blind to a 100 ns selector change — and the results file says so;
   the precision claim is M.1 vs the control. Do not invent a `fallback`
   selector.
3. Allocation count (M.9): a counting `#[global_allocator]` in the bench
   binary, the same `Counting` wrapper shape as
   `crates/fah-rules/tests/url_lookup_alloc.rs`, sampled around one
   `forward` per strategy against the loopback mock; report the two numbers
   (must be equal). p2.6-05's `tests/forward_alloc.rs` asserts the same
   invariant as a test; this arm reports the number.
4. A/B: `git worktree add` the pre-p2.6-05 commit, build its
   `forward_udp_*` benches, run in the same session, same pin, alternating
   runs ≥ 3 each. Pre-change `upstream_select` does not exist; the A/B
   applies to the `forward_udp_*` arms and the control.
5. Results file `docs/code-review/phase2.6/p2.6-08-microbench-review.md`:
   device, pin, commit pair, criterion CI per arm, RB5009-equivalent via
   the 9× factor (not a clock reading), allocation counts.

## Benchmarks / gates

- M.1 ≤ `noop + 10 ns` x86 and < 111 ns x86 ("at or below the control" is
  unattainable by construction — benchmarks §S1-M); the "one relaxed load,
  early exit" claim is reported as an instruction count from the
  disassembly (`cargo asm` or `objdump -d` on the bench binary) or
  `perf stat`, not inferred from timing. M.2–M.4 < 111 ns x86; M.5 < 22 ns
  x86; M.7 no unbounded retry (claims per batch == 1, time bounded).
- `forward_udp_answered` `adaptive` vs `fallback`: the three-clause M.8 rule
  (benchmarks doc §S1-M acceptance) — K ≥ 6 pre-declared alternating pairs, the
  95 % t-CI of the mean paired delta contains 0, its upper bound < +10 %, no
  single pair > +10 % (root CLAUDE.md blocker). Criterion's per-pair within-run
  CIs are descriptive, not the gate.
- Control within ±2 % across the A/B or the session is void — rerun.
