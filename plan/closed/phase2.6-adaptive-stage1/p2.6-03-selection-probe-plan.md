## Implementation changes

In `health.rs` (same module; the selector is a function over `&[Health]`):

1. `pub enum Selected { Healthy, Probe, Forced }` and
   `pub struct Candidate { pub id: u8, pub selected: Selected }`.
2. `pub fn select(health: &[Health], start: usize, now: impl FnOnce() -> u64, claim: bool) -> Option<Candidate>`
   — **one pass**, `start..len`, in config order, judging each word where
   the pass meets it:
   - `State::Healthy` → return `Healthy`. If no earlier word was
     non-Healthy, `now` was never evaluated: the all-Healthy path is
     clock-free (S1.11).
   - `State::Penalized`: evaluate `now` here if not yet evaluated (an
     `Option<u64>` memo — the closure is `FnOnce`, called at most once per
     pass). If `deadline <= now` **and `claim`**: attempt
     `compare_exchange_weak(word, pack(Probing, round, cf, deadline), Relaxed, Relaxed)`;
     on success → return `Probe`; on failure continue the pass without
     retrying (a lost race means someone else claimed it — M.7 must not
     spin). If `deadline <= now` and `!claim`, or `deadline > now`: skip,
     remembering this word's `timestamp_ms` as a forced candidate.
   - `State::Probing` → skip, remembering its `timestamp_ms` as a forced
     candidate.
   - Pass exhausted with nothing returned → the remembered word with the
     smallest `timestamp_ms` → `Forced`; no store. (Every word from `start`
     was Penalized or Probing, so a candidate exists.)
   - `None` only when `start >= len`.
   Not "first Healthy, else first due": a due endpoint **ahead** of a Healthy
   one must be probed, or a recovered primary stays Penalized until the
   secondary fails (validation B1). The pass judges each endpoint once, in
   order.
3. `claim` is the whole of the Ignore-mode and one-probe-per-query contract
   (S1.5, S1.8): `false` turns a due endpoint into a skip. The caller
   (p2.6-05) passes `mode == Record && !probed`. Plain `bool` — this task
   does not reference `HealthMode` (p2.6-04) and p2.6-04 does not change
   this signature (validation B2).
4. The function owns no loop over attempts: the caller (p2.6-05) calls
   `select(.., id + 1, ..)` after a failed attempt, which is how the scan
   "continues from the next endpoint" (S1.5).
5. The forced candidate set includes `Probing` endpoints: if every endpoint
   is Penalized or Probing, the forced candidate may be one with a probe in
   flight; that is still one packet sent, and it claims nothing. Its outcome
   lands under whatever row the word shows then — on a Probing word a
   failure bumps the round (S1.3); deadline/round invariance is asserted on
   the Penalized row only (validation H3).

## Tests

Unit tests in `health.rs`, synthetic `[Health; n]`:

- Boot: 2 and 8 Healthy → `id 0`, `Selected::Healthy`, and the `now` closure
  is never invoked (assert with a flag).
- First Healthy after k Penalized-not-due → `id k`; the closure invoked
  exactly once.
- **Due ahead of Healthy** (`claim = true`): `[due, Healthy]` → `id 0`,
  `Probe`; the word reads `Probing` with round, `cf` and deadline preserved.
  This is the test the two-pass reading fails.
- Due behind Healthy: `[Healthy, due]` → `id 0`, `Healthy`; the due word
  unchanged (reached only on continuation).
- G1 #6 unit: all Penalized, deadlines in the future, distinct → the
  smallest deadline's id, `Forced`; every word unchanged afterwards;
  `probes` untouched (the selector never touches counters — assert the
  whole `Health` byte-for-byte equal). Then `record(HardFailure)` on it:
  deadline and round unchanged, `cf` moved.
- G1 #8: `std::thread::scope`, N ≥ 8 threads, one due endpoint, each thread
  calls `select(.., claim = true)` once; exactly one `Probe`. Variant A: no
  other endpoint → the rest `Forced` on id 0. Variant B: `[due, Healthy]` →
  the rest `Healthy` on id 1, and the single `Probe` is on id 0.
- G1 #16 unit (`claim = false`): `[due, Healthy]` → `id 1`, `Healthy`, the
  due word byte-for-byte unchanged; `[due]` → `id 0`, `Forced`, word
  unchanged; `[due, due]` → the smaller `timestamp_ms`, `Forced`, both
  unchanged.
- Deadline boundary: `deadline == now` is due; `deadline == now + 1` is not.
- Continuation: `start = 1` skips id 0 even if Healthy; `start = len` → `None`.
- Mixed: `[Penalized future, Probing, Healthy]` → id 2, closure invoked once;
  `[Penalized future, Probing]` → the smaller `timestamp_ms` of the two,
  `Forced`.

## Contradictions — resolved by the owner (2026-08-23)

- None against the code. **Accepted:** forced selection considers
  Penalized *and* Probing endpoints by earliest `timestamp_ms`; a pool whose
  every endpoint is Probing still returns a candidate, and the forced
  attempt claims nothing. S1.3's "earliest deadline" is read that way. A
  forced failure landing on a Probing word bumps the round (S1.3 Probing
  row); the invariance assertion applies to the Penalized row (H3).
- **B1 (validation 2026-08-23, accepted): one pass, not two.** The earlier
  draft's "first Healthy, else first due" never probed a due endpoint while
  any Healthy endpoint existed, so a recovered primary stayed Penalized until
  the secondary failed. Spec S1.5 now reads as step 2 above; G1 #8 variant B
  pins it.
- **B2 (accepted): `claim: bool`.** Ignore mode must not claim — a claim
  with no recorded outcome leaves the word Probing with no probe in flight.
  The flag is a plain `bool` here; `HealthMode` (p2.6-04) maps to it in
  p2.6-05. The same flag carries the one-probe-per-query rule.
