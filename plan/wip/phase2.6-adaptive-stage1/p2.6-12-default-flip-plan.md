## Implementation changes

1. Confirm in the review file: every deployment-tier gate passed
   (quote p2.6-11's lines). If any is open, stop.
2. `default_strategy()` → `Adaptive`. If S1-G4 derived a different
   `penalty_failures`, `default_penalty_failures()` changes here too, with
   the evidence cited.
3. **Remove `Fallback`**: variant, `FromStr` arm, `with_tls_config` match,
   the `fallback` branch of `forward`, `status()`'s arm, the `strategy`
   field on the pool if nothing else reads it, `degraded()`'s old rule.
   `FromStr` error string becomes `"adaptive"` (or the enum is reduced to
   one variant and the key kept for forward compatibility — owner's call;
   `deny_unknown_fields` makes removing the *key* a boot failure, so the
   key stays).
4. A config with `strategy = "fallback"` fails validation with a message
   saying the value was removed and `adaptive` is the only strategy.
   Deploy order stays binary first, config second — and the env opt-in
   from p2.6-11 is now redundant; propose its removal from the container
   (owner runs it).
5. Plain `consecutive_failures` on `UpstreamServer` deleted if C3 option
   (a) was taken; `run_buckets` stays (fed from `Transition::closed_run`).
6. Tests: run the old suite under `adaptive`. Any test that asserted
   ordered-walk-only behaviour (for instance
   `all_upstreams_dead_errors_and_counts_failures` counting one failure per
   server per query, or `falls_back_past_a_timing_out_upstream_within_one_extra_window`
   timing the second query) is updated to the Stage 1 equivalent and the
   change listed in the review file with the reason. Tests that pass
   unchanged stay unchanged.
7. Benches: drop the `fallback` arms.
8. Docs (each owner-approved): CONFIGURATION.md `[dns.upstreams]` default
   and value set; API.md if it names strategies; `docs/project-state.md`
   rewritten; the spec's status line marked shipped with the build.
