# P2.6-01 — Configuration Surface

**Phase:** 2.6 · **Depends on:** — · **Model:** Opus

## Goal

`[dns.upstreams]` accepts `strategy = "adaptive"` and `penalty_failures`, with
compiled-in defaults that boot every existing config unchanged, and both can
be set from the environment so opt-in on the RB5009 is a container env change
rather than a TOML edit inside the container.

## Context

Spec S1.13 (configuration surface — exactly one new enum variant and one new
key), S1.14 (`#[serde(default)]`, deploy order binary-first), S1.2 (8-endpoint
cap). `deny_unknown_fields` on the root `Config` makes every key permanent; do
not add anything the spec lists under "Not a key".

## Scope

- `strategy` enum gains `adaptive`; default stays `fallback`.
- `penalty_failures` (consecutive transport failures before Penalized),
  `#[serde(default)]` = 2, validated `≥ 1`.
- Validation: at most 8 `[[dns.upstreams.servers]]` entries, alongside the
  existing non-empty check. `EndpointId` is a `u8` and the scan is linear.
- Validation: `timeout_ms` in `1..=10_000` (spec S1.6 — outside that range
  the penalty schedule degenerates). The one change to an existing key.
- `env.rs` override entry for `penalty_failures`, following the existing
  pattern at `crates/fah-config/src/env.rs`. The `strategy` override already
  exists there (`env.rs:76`) and is the router opt-in path.
- No policy struct here; `fah-dns` builds it from these values in `p2.6-05`.
- The type gains a field, so every `DnsUpstreamsConfig { .. }` struct literal
  in the workspace gains `penalty_failures` — nine sites outside `fah-config`
  (listed in the plan). That is the only edit to those files; no assertion
  changes.

## Acceptance criteria

- A config written for the current release parses and validates unchanged.
- `strategy = "adaptive"` and `penalty_failures = 3` round-trip through
  `GET /api/v1/config` shape (serde only; the endpoint is unchanged).
- Nine servers fail validation with a message naming the cap;
  `penalty_failures = 0` fails validation; `timeout_ms = 0` and
  `timeout_ms = 10_001` fail validation.
- Env override tests for both keys in the existing env test module.
- The nine literal sites compile with the field added and their tests pass
  with assertions unchanged (`git diff` on each shows the one added line).
- Gates green. No `.md` edited — CONFIGURATION.md is `p2.6-07`.

## Out of scope

Any behaviour change under either strategy; `penalty_base_ms`,
`penalty_max_ms`, `query_deadline_ms` or any Stage 2/3 key.
