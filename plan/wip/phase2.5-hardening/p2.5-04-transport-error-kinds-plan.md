# Plan — p2.5-04 Transport Error-Kind Fidelity

## Summary

One classifier replaces the three `io::Error::other` erasure sites on the
DoT/DoH paths so timeout / path-failure / TLS-failure are distinguishable
by `ErrorKind`, and the RCODE-is-not-a-failure invariant gets its pinning
test. Depends on p2.5-03 (same file, restructured `query()` arms).

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Classifier | `fn transport_error(err: ProtoError) -> io::Error`, private to `crates/fah-dns/src/upstream/encrypted.rs` |
| Call sites replaced | encrypted.rs:143 (DoT connect), :154 (DoH connect), :190 (`send_once`) — all three, no others exist |
| Pass-through kinds | walk `source()` chain; first `std::io::Error` found donates its kind verbatim, whatever it is — no allowlist (an allowlist would silently re-erase future kernel kinds) |
| TLS classification | if the chain contains a `rustls::Error` (via downcast) **or** the `ProtoError` display chain is reached without any `std::io::Error`, and the error originates in the TLS/HTTPS stream layer → `ErrorKind::InvalidData` |
| Precedence | io-error-in-chain wins over TLS classification (a TLS stream's underlying `ConnectionReset` stays `ConnectionReset`); `TimedOut` is produced only by the existing timeout wrappers, never by the classifier |
| Fallback | no io error, no rustls in chain → `ErrorKind::Other` (today's behavior) |
| Message | full `error_chain`-style text preserved in every case |
| Pinning test location | `crates/fah-dns/src/upstream/mod.rs` test module |

`InvalidData` is thereby the reserved meaning "TLS/protocol-layer path
failure" on these transports — recorded in the review file as the
contract Stage 1's S1.4 tier cites. Nothing else on these paths may
produce `InvalidData`: hickory's DNS wire-decode errors surface from
`send_once` as `ProtoError` without an io source and without rustls —
those fall to `Other`, which is correct (a malformed answer is not a path
failure).

## Implementation units

**U1 — classifier + call sites.** Implement `transport_error`; replace
the three `map_err(io::Error::other)` sites. The pool's behavior is
untouched — this changes what errors say, not what `forward()` does.

**U2 — classification tests** (encrypted.rs test module, existing rig):
- refused: connect to a port with no listener → `ConnectionRefused`.
- timeout: silent-after-accept server → `TimedOut` (via p2.5-03's path).
- TLS: server presenting a cert signed by a different CA than the client
  trusts → `InvalidData`.
- synthetic chain: `ProtoError` wrapping
  `io::Error::from(ErrorKind::NetworkUnreachable)` fed directly to
  `transport_error` → `NetworkUnreachable` (no live unreachable route
  needed).

**U3 — RCODE pinning test (S1-G1 #5).** Mock transport in
upstream/mod.rs tests returning decoded `SERVFAIL`, `NXDOMAIN`, `REFUSED`
(one case each): assert `failures` delta 0, `consecutive_failures`
becomes 0 from a seeded nonzero value, walk ends (secondary's `attempts`
delta 0).

## Invariants (must hold before and after)

- `forward()`'s fallback ordering, timing budget, and counter movements
  are unchanged.
- Only genuine timeouts carry `TimedOut` (p2.5-03's invalidation trigger
  depends on it).
- `InvalidData` on these paths means TLS/protocol path failure and
  nothing else.
- Existing encrypted-transport tests pass with at most `kind()`
  assertions updated.

## Out of scope (closed paths)

- No consumption of the classes (selection, penalties, alarms — Stage 1).
- No plain-UDP changes (already faithful), no `resolve_host` changes.
- No public error type, no new enum — `io::Error` kinds are the whole
  surface.
- No logging changes (the debug line at mod.rs:198 already prints the
  chain).
