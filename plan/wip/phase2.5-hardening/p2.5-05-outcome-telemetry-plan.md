# Plan — p2.5-05 Outcome Telemetry: Client-Visible Failure and Endpoint Attribution

## Summary

Two additive event/telemetry changes: a served SERVFAIL becomes countable
(synthesized vs relayed vs refused), and a forwarded query's event names
the answering endpoint by index. Everything rides `/telemetry` and the WS
event stream — no query log, no Prometheus (p2-09 stands).

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Outcome enum | `fah_model::AnswerOutcome { Answered, ServfailSynthesized, ServfailRelayed, RefusedRelayed }`, `#[serde(rename_all = "snake_case")]`, `Default = Answered`, declared in `crates/fah-model/src/query_event.rs` |
| Event fields | `QueryEvent` gains `answer: AnswerOutcome` (`#[serde(default, skip_serializing_if = "is default")]`) and `endpoint: Option<u8>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`) |
| `upstream_used` | **kept unchanged this release** (wire compat; pinned tests untouched); retirement noted in the review file, executed no earlier than the next breaking release |
| Forward outcome | `pub struct ForwardOutcome { pub message: Message, pub endpoint: u8 }` declared in `crates/fah-dns/src/upstream/mod.rs` next to the `Forwarder` trait — **not** in fah-model (it never crosses the event channel) |
| Trait contract | `Forwarder::forward` returns `io::Result<ForwardOutcome>`; `UpstreamPool` fills `endpoint` with the walk index (`u8`, config order); every mock/bench implementor fills `0` |
| Endpoint on event | set only on the pipeline's forward `Ok` arm; `None` for blocks, cache hits, SWR stale serves, stale-after-failure, and synthesized SERVFAIL |
| Tagging (pipeline.rs:384-419) | `Ok` + `response_code == ServFail` + no stale fallback taken → `ServfailRelayed`; new explicit check `Ok` + `response_code == Refused` → `RefusedRelayed` (no existing branch — add it in the `Ok` arm before the store; the store call itself is unchanged); `Err` arm's synthesized SERVFAIL → `ServfailSynthesized`; everything else `Answered` (a stale serve that masked a failure is `Answered` — the masking is already counted via `cache_stale` + `StaleServe::AfterForwardFailure`) |
| Counters | three `AtomicU64` on `fah_metrics::Metrics`: `answers_servfail_synthesized`, `answers_servfail_relayed`, `answers_refused_relayed`; incremented in `record()` from `event.answer` |
| Export | new `fah_model::AnswerCounters { servfail_synthesized, servfail_relayed, refused_relayed }` embedded as `answers` in `fah_model::DnsCounters` (EngineTelemetry → `/telemetry`) and mirrored as three fields in `MetricsSnapshot` (perf sampler picks them up like every other counter) |

## Implementation units

**U1 — model** (`crates/fah-model/src/query_event.rs`): enum + two
fields; attribution is attached with
`QueryEvent::with_outcome(answer, endpoint)`, the same chained-setter shape
`under_policy` uses. `QueryEvent::new` is left at six parameters because an
eighth trips `clippy::too_many_arguments` on a public constructor. The
pipeline is the only producer that sets a non-default outcome, and its tests
assert the outcome on every path. `AnswerCounters` in
`crates/fah-model/src/engine.rs` beside `DnsCounters`.

**U2 — trait + pool** (`crates/fah-dns/src/upstream/mod.rs`):
`ForwardOutcome`; `forward` returns it (walk index captured via
`enumerate()`); `resolve_host`/`lookup` (:115-161) take `.message` and
discard the index; SWR (`swr.rs` refresh forward) discards likewise. The
implementor sweep is ~11 sites including bench forwarders
(`crates/fastadhunter/benches/pipeline.rs:145`,
`crates/fah-dns/benches/cache.rs:31`) — p2.5-09's A/B must account for
the bench-source diff.

**U3 — pipeline tagging** (`crates/fah-dns/src/pipeline.rs`): thread
`answer` + `endpoint` from `resolve()`'s return through `handle()` into
`emit_event` (:422-440); extend the tuple `resolve()` returns rather than
adding parameters piecemeal.

**U4 — metrics + snapshot** (`crates/fah-metrics/src/registry.rs`):
three atomics, increments in `record()` (no interaction with the
verdict/cache/stage logic — purely additive), export in
`engine_telemetry()` (:215+) and `snapshot()` (:272+); passthrough in the
fah-api telemetry DTO if it re-declares `DnsCounters` (it consumes the
fah-model type — verify, expect zero API-crate change).

**U5 — consumers (owner-gated).** API.md event + telemetry deltas
proposed for approval. tui-monitor: no code change required (serde
defaults); verify by deserializing a captured pre-change event JSON in a
fah-model test.

## Invariants (must hold before and after)

- `hits + misses == pass + allow` and the stale identity — asserted
  explicitly in the new tests; the new counters are a parallel axis and
  re-route nothing.
- A synthesized SERVFAIL still counts pass + miss + forward-stage exactly
  as today.
- Hot-path cost: one enum + one `Option<u8>` copied per event; zero
  allocations added.
- No serialized field renamed or removed; old event JSON deserializes
  (defaults).
- fah-model purity: data + derives only.

## Tests (all objectively checkable)

1. Forward failure, no stale → `answer == ServfailSynthesized`,
   `endpoint == None`, `answers_servfail_synthesized` +1, and the
   invariants above hold across the case matrix.
2. Upstream answers SERVFAIL (no stale entry) → `ServfailRelayed`,
   `endpoint == Some(0)`.
3. Upstream answers REFUSED → `RefusedRelayed`, endpoint set, response
   relayed unchanged.
4. Primary fails, secondary answers → `endpoint == Some(1)`.
5. Cache hit / block / SWR stale serve → `Answered`, `endpoint == None`.
6. Pre-change event JSON fixture (no `answer`, no `endpoint`)
   deserializes to `Answered`/`None`.
7. `/telemetry` JSON carries `counters.dns.answers.{servfail_synthesized,
   servfail_relayed,refused_relayed}`.

## Out of scope (closed paths)

- No run-length buckets (p2.5-06), no per-client failure attribution, no
  histogram or latency-stage changes, no persisted per-query records.
- No `upstream_used` removal or rename; no event-schema versioning.
- No `RequestEvent` (HTTP) changes.
- No retry/fallback behavior changes anywhere.
