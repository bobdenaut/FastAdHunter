# P2.5-11 — HTTP Refusal Log Hygiene

**Phase:** 2.5 · **Depends on:** p2.5-09 · **Model:** Opus

## Goal

A client that keeps sending requests the egress policy refuses cannot fill
the operator's log, and the refusals it suffers are countable where every
other outcome is — `/telemetry`.

## Context

Observed on the RB5009 2026-08-23 (0.2.18): one phone (`192.168.10.18`)
doing plain HTTP to a public IP literal; `[egress] allow_ip_literal_hosts =
false` refuses each request and `crates/fah-http/src/proxy.rs:322` logs
`WARN fah_http::proxy: refused: unusable Host … reason="host_ip_literal"`
per request — 138 lines in the router's log buffer, bursts of 1–3/min,
indefinitely. A refusal is a policy outcome, not an operator warning (same
reasoning as RCODE-is-not-a-failure, p2.5-04), and the log line is a
client-driven, unbounded output (hard rule 4 in spirit).

`ProxyCounters.refused_claim` already counts it, but `ProxyCounters::snapshot()`
→ `ProxyStats` is never read by the binary: the counter reaches neither
`/telemetry` nor `fah-metrics`. Silencing the log without surfacing the
counter would make refusals invisible.

## Scope

- `proxy.rs:322`: `warn!` → `debug!`, same fields.
- Surface the proxy's refusal count on `GET /api/v1/telemetry` under
  `counters.http` (one new key, e.g. `refused`), read from
  `ProxyCounters::snapshot()` in the binary's telemetry poll — the same place
  the DNS counters are assembled. Zero hot-path cost: the `fetch_add` already
  exists; the read is the binary's 10 s telemetry poll.
- `fah-model` `HttpCounters` gains the field with `#[serde(default)]` so
  retained perf rows written before it still deserialize (p2.5-05 pattern).
- Tests: a refused request increments the surfaced counter; a pre-change
  `HttpCounters` JSON still deserializes.
- API.md §`/telemetry` `counters.http` and CONTEXT.md (if "refusal" is to be
  binding vocabulary) — owner-approved at execution.

## Acceptance criteria

- Gates green.
- A refused request produces no line above `debug`.
- `counters.http.refused` present on `/telemetry` and increments on the
  dev box under the p2-04 proxy tests' refusal case.
- Live, next deploy: the router log stops carrying the line; the counter on
  `/telemetry` keeps moving for the phone.

## Out of scope

Per-peer rate limiting (would add per-client state); changing the egress
policy or its default; the `allow_ip_literal_hosts` semantics; router-side
exemptions.
