# Plan — p2.5-03 Encrypted Transport Reconnect on Timeout

## Summary

Any timed-out DoT/DoH exchange invalidates the pooled connection
(generation-checked), so the next exchange reconnects — a blackholed
connection after an IPv6 prefix rotation heals in one timeout window,
making spec S1.15 true. Decision carried (session-settled: user-directed):
single-timeout invalidation, not an N-consecutive threshold.

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Slot shape | `slot: Mutex<Slot>` replacing `Mutex<Option<DnsExchange<TokioRuntimeProvider>>>` (`crates/fah-dns/src/upstream/encrypted.rs:44`), where `struct Slot { generation: u64, exchange: Option<DnsExchange<TokioRuntimeProvider>> }` |
| Generation semantics | starts 0; incremented every time `exchange` is **set** (in `connected` and `reconnect`); never incremented on clear |
| Invalidate API | `async fn invalidate_if_current(&self, generation: u64)` — lock, `if slot.generation == generation { slot.exchange = None }` |
| What invalidates | every `ErrorKind::TimedOut` from `send_once`, pooled **or** fresh; plus a fresh connection's non-timeout `send_once` error (clears its own just-stored exchange) |
| What does not | non-timeout pooled error keeps today's reconnect-once-and-retry path; connect-phase errors store nothing so clear nothing |
| Error surface | unchanged — timeout still returns `Err` to the pool with no in-query retry; failure counters move only in the pool's `Err` arm as today |

## Implementation units

**U1 — `Slot` + generation.** Rework `connected()`
(encrypted.rs:99-110): returns `(DnsExchange, bool fresh, u64 generation)`
— on pooled hit, the stored generation; on store, `generation += 1` then
return the new value. `reconnect()` (:112-120) likewise bumps on store and
returns the new generation with the exchange. Add
`invalidate_if_current`.

**U2 — `query()` arms** (encrypted.rs:73-97). New match on
`send_once` result:

```text
Ok(response)                          → Ok(response)
Err(e) if e.kind() == TimedOut        → invalidate_if_current(gen); Err(e)
Err(e) if fresh                       → invalidate_if_current(gen); Err(e)
Err(_) /* pooled, non-timeout */      → reconnect(); send_once() retry
                                        (today's path; a TimedOut from the
                                        retry also invalidates via the
                                        retry's own generation)
```

The `mux_timeout = attempt_timeout * 2` setup stays (send_once must fire
first so this classification runs); the stale keep-the-connection
rationale comment at :86-88 is **deleted** (hook permits deletion only)
and the reversal is recorded in the review file.

## Invariants (must hold before and after)

- A query's worst-case wall time per server is unchanged (no new awaits
  beyond one uncontended slot lock on the error path).
- `attempts`/`failures`/`consecutive_failures` movements are byte-for-byte
  the pool's existing ones; this change adds none.
- `handshakes` increments exactly once per actual `connect()` — the
  reconnect-churn observability.
- A concurrently installed newer exchange is never dropped by an older
  query's invalidation (generation check).
- Plain-UDP transport untouched.

## Tests (all objectively checkable, on the existing throwaway-CA rig)

1. **Blackhole heal:** TLS server answers query 1, then reads-but-never-
   writes. Query 2 → `Err` with `kind() == TimedOut` within
   `attempt_timeout + 50 ms`. Server restored; query 3 → `Ok`, and
   `handshakes()` is exactly +1 versus after query 1.
2. **Generation race (deterministic):** store an exchange (gen G), call
   `reconnect` (gen G+1), call `invalidate_if_current(G)` → slot still
   holds the G+1 exchange; `invalidate_if_current(G+1)` → slot empty.
3. **Fresh-error clear:** first-ever query against a server that accepts
   TLS then closes before answering → `Err`, and the next query performs
   a fresh handshake (`handshakes()` +2 total, proving no dead pooled
   reuse).
4. **Idle-close unchanged:** existing test stays green (pooled
   non-timeout error → reconnect once, answered within the same query).

## Out of scope (closed paths)

- No error-kind mapping changes (p2.5-04, which depends on this landing
  first and must keep `TimedOut` mapping exact — it is this task's
  trigger).
- No connect-ahead/eager reconnect, no keepalive probing, no pool of
  multiple connections per server.
- No Stage 1 penalty/probe logic; no spec edits (S1.15/S1.7 become true
  as written).
- No telemetry additions (churn reads from the existing `tls_handshakes`).
