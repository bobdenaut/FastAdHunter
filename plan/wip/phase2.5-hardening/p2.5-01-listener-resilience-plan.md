# Plan — p2.5-01 Listener Resilience and a Real Healthcheck

## Summary

DNS UDP/TCP listener loops survive transient socket errors with bounded
backoff, escalate to process exit when the socket is persistently broken,
and `--healthcheck` proves the DNS path answers via a NotImp probe that
cannot depend on upstream health. All decisions below are final; implement
as specified.

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Backoff | initial 10 ms, ×2 per consecutive error, capped at 1 s |
| Escalation threshold | 40 consecutive errors with no successful receive between them (≈ 34 s of backoff) |
| Error classification | none — every `recv_from`/`accept` error goes through the same retry policy; the threshold, not error inspection, decides fatality |
| Escalation action | listener loop returns; binary logs at `error` and exits the process with `ExitCode::FAILURE` |
| Helper placement | new module `crates/fah-dns/src/backoff.rs`, `pub(crate)` |
| Fatal signaling | `tokio::sync::mpsc::channel::<ListenerDied>(1)` owned by `Server`; each listener task sends on return |
| Healthcheck probe | opcode `Status` query, blocking `std::net::UdpSocket`, 2 s read timeout, target `127.0.0.1:<configured dns.listen port>` always |
| Healthcheck exit codes | 0 all checks pass; 1 otherwise, message names the failed check (`config` or `dns-probe`) |

## Implementation units

**U1 — `crates/fah-dns/src/backoff.rs`.** New module:

```text
pub(crate) struct RetryPolicy { consecutive: u32 }
pub(crate) enum RetryDecision { Sleep(Duration), Fatal }
impl RetryPolicy {
    pub(crate) fn new() -> Self
    pub(crate) fn on_error(&mut self) -> RetryDecision   // 40th error → Fatal
    pub(crate) fn on_success(&mut self)                  // resets counter
}
```

Pure, no clock, no I/O — the caller sleeps. Constants in this module:
`BACKOFF_INITIAL = 10 ms`, `BACKOFF_MAX = 1 s`,
`FATAL_CONSECUTIVE_ERRORS = 40`. Unit-tested here.

**U2 — loop rewrites.** `crates/fah-dns/src/udp.rs` `run` and
`crates/fah-dns/src/tcp.rs` `run` change return type `()` →
`ListenerDied` (new `pub(crate) struct ListenerDied { pub(crate) last_error: std::io::Error }`,
declared in `crates/fah-dns/src/server.rs`). On error:
`policy.on_error()` → `Sleep(d)` ⇒ `warn!` + `tokio::time::sleep(d)` +
`continue`; `Fatal` ⇒ `return ListenerDied { last_error }`. On successful
receive/accept: `policy.on_success()`. The per-datagram spawn, the
per-connection spawn, and `is_client_disconnect` handling are unchanged.
The falsified doc comments `udp.rs:13` ("until the socket errors
unrecoverably") and `tcp.rs:27` are **deleted** (the no-comments hook
permits deletion only; record the deletions in the review file).

**U3 — `Server` escalation API.** `crates/fah-dns/src/server.rs`
(`Server` at :24, `handles: Vec<JoinHandle<()>>` at :29): `serve` creates
the mpsc(1) channel; each listener task becomes
`spawn(async move { let died = run(...).await; let _ = tx.try_send(died); })`.
`Server` stores the receiver and exposes
`pub async fn fatal(&mut self) -> ListenerDied` (awaits `recv`; if all
senders dropped without a send — impossible by construction — pend
forever). `shutdown()`'s abort behavior is unchanged.

**U4 — binary wiring.** In `crates/fastadhunter/src/main.rs`, where the
engine currently awaits shutdown, add the fatal arm to the existing
`tokio::select!` (or create one wrapping the shutdown await if none
exists at that point): on `server.fatal()` → `error!` with the last
error, run the normal shutdown/abort path, return `ExitCode::FAILURE`.

**U5 — healthcheck probe.** In the `args.healthcheck` branch
(main.rs:121-145): keep `Config::load_readonly`; on success, build the
probe with `hickory_proto::op::Message`: `MessageType::Query`,
`OpCode::Status`, no questions, random id. Send via blocking
`std::net::UdpSocket` bound to an ephemeral port, `set_read_timeout(2 s)`,
to `127.0.0.1:<config.dns.listen port>` (always loopback v4 — the
listener clears `IPV6_V6ONLY`, so a `::` bind answers v4-mapped loopback;
a v4 bind answers directly). Any reply of ≥ 12 bytes with the same id =
pass (the pipeline answers non-`Query` opcodes with NotImp before
rules/cache/upstream — `crates/fah-dns/src/pipeline.rs:247-255`). Config
failure prints `healthcheck failed: config: <err>`; probe failure prints
`healthcheck failed: dns-probe: <err>`; both exit 1. Dockerfile
HEALTHCHECK unchanged.

## Invariants (must hold before and after)

- Happy path: zero added work per datagram/accept except one
  `RetryPolicy::on_success` counter store per receive.
- A blocked/allowed/forwarded query's code path is untouched.
- `Server::shutdown` still aborts every listener task.
- The healthcheck never opens the config file for writing and never
  touches rules, cache, or upstreams.

## Tests (all objectively checkable)

1. `backoff.rs` unit: 39 errors → `Sleep` with the documented progression
   (10, 20, 40, … capped 1000 ms); 40th → `Fatal`; `on_success` after 39
   errors resets so the next error yields `Sleep(10 ms)`.
2. Integration (fah-dns): a `Server` on ephemeral ports serves a query,
   then keeps serving after a burst of client-side garbage (existing
   behavior, re-asserted).
3. Healthcheck integration (fastadhunter `tests/`): binary with a live
   ephemeral listener → exit 0; with a config naming a port where nothing
   listens → exit 1 within 3 s and stderr contains `dns-probe`; with an
   invalid config → exit 1 and stderr contains `config`.
4. DNS benches: run and record in the review file; no happy-path change
   expected — any regression > 10 % blocks per PERFORMANCE.md.

## Out of scope (closed paths)

- No supervision/respawn framework, no restart-in-place of a listener,
  no rebind attempt (impossible post-privilege-drop, ADR-0004).
- No error-kind-specific retry tuning; no config keys for backoff or
  threshold (constants only).
- No HTTP/API listener changes (its loop already retries).
- No healthcheck probing of TCP/53, the API, or upstreams.
- No RouterOS-side restart configuration.
