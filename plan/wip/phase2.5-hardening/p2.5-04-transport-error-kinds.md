# P2.5-04 — Transport Error-Kind Fidelity

**Phase:** 2.5 · **Depends on:** p2.5-03 · **Model:** Fable

## Goal

Encrypted transports preserve enough `io::ErrorKind` fidelity that the
accepted spec's S1.4 failure tiers (hard failure vs path failure) are
implementable, and the RCODE-is-not-a-failure invariant is pinned by test.

## Context

Reconciled §3.2 / GAR-A risk 4b: `map_err(io::Error::other)` at
`crates/fah-dns/src/upstream/encrypted.rs:143` and `:154` collapses
hickory/rustls connect and exchange errors — including certificate
failures — into `ErrorKind::Other`. S1.4 distinguishes Timeout (hard
failure) from `NetworkUnreachable`/`ConnectionRefused`/TLS failure (path
failure, penalized at 1); that tier cannot be implemented on an error
surface that erases kinds. Plain UDP already preserves kinds. Separately,
S1-G1 gate 5 requires a pinning test that DNS RCODEs never move failure
counters — structurally true today (`upstream/mod.rs:187-203`, counters
move only in the `Err` arm) but unpinned.

## Scope

- Map hickory/rustls errors to meaningful kinds in the DoT/DoH connect and
  exchange paths: kernel kinds (`ConnectionRefused`, `NetworkUnreachable`,
  `HostUnreachable`, `TimedOut`) pass through; TLS/certificate failures map
  to a distinguishable, stable classification (a dedicated kind or a
  wrapper the pool can match on — smallest mechanism that lets a future
  caller separate "path/TLS failure" from "other").
- No behavior change in the pool: this task changes what errors *say*, not
  what the pool *does* with them.
- Pinning test: a decoded `SERVFAIL`, `NXDOMAIN`, and `REFUSED` response
  each reset `consecutive_failures` and increment no failure counter
  (S1-G1 #5).

## Acceptance criteria

- Unit tests per failure class: refused, unreachable, timeout, TLS/cert
  failure each observable as their own classification from the caller's
  side of the transport.
- RCODE pinning test in place.
- Gates green.

## Out of scope

Using the classifications for selection (that is Stage 1); alarm or
telemetry changes.
