# P2.5-07 — SWR Claim Lease vs Worst-Case Upstream Walk

**Phase:** 2.5 · **Depends on:** — · **Model:** Fable

## Goal

The SWR refresh claim lease provably exceeds the worst-case upstream walk,
so an 8-endpoint configuration cannot double-refresh.

## Context

Reconciled §3.3 (a GAR-B catch confirmed against the code): the refresh
claim lease is 5 s (`crates/fah-dns/src/cache.rs`, `REFRESH_LEASE`), while
the ordered walk's worst case is `servers.len() × timeout_ms` — with the
spec's 8-endpoint cap and the default 800 ms timeout that is 6.4 s. A walk
outliving the lease lets a second worker claim the same stale entry and
duplicate the refresh. Today's default (2 servers, 1.6 s) is safe; the
8-endpoint cap the spec adds makes the arithmetic reachable without
Adaptive ever shipping.

## Scope

- Guarantee lease > worst-case walk by construction: derive the lease from
  the configured `servers.len() × timeout_ms` plus a margin, or validate
  the configuration at load (reject/clamp combinations whose walk exceeds
  the lease) — whichever is the smallest correct change. Deriving is
  preferred if it stays a one-place computation.
- The 30 s failure cooldown and the drop-not-backpressure contract
  (ADR-0005) are unchanged.
- Record the chosen mechanism in the review file so the spec's S1.9
  interaction section can cite it.

## Acceptance criteria

- Test: a configuration whose walk would exceed the old fixed lease cannot
  double-claim (either the lease scaled or the config was rejected).
- Existing SWR claim/lease/cooldown tests still green.
- Gates green.

## Out of scope

The 8-endpoint config cap itself (Stage 1 work per the spec); SWR EDNS
(explicitly out of this phase's scope — only this lease check is in).
