# P2.5-08 — Hygiene: Token, Layering Guard, Stale Docs

**Phase:** 2.5 · **Depends on:** — · **Model:** Opus

## Goal

The tracked bearer token is gone and rotated, the layering guard covers the
whole workspace, and the three documented contradictions the GAR found are
reconciled.

## Context

Reconciled §6 hygiene items, each cheap and standing:

1. `tui-monitor/config.toml` is git-tracked and holds a live bearer token —
   full admin over the household resolver's API (flagged since
   project-state.md:177, still present).
2. The layering guard walks only `crates/` — tui-monitor's edges are
   unchecked, `checked == 11` bakes the blind spot in, renamed deps
   (`x = { package = "fah-dns" }`) bypass the key filter, and
   `[build-dependencies]` / `[target.'cfg(...)'.dependencies]` tables are
   unscanned (`crates/fastadhunter/tests/layering.rs`).
3. Doc contradictions: `docs/deploy-rb5009.md` §"IPv6 is not covered" is
   stale against p2-14's verified v6 interception (p2-14 wins);
   `docs/routeros-traps.md:152` and `fah-metrics`' crate doc still name the
   removed `/metrics`/Prometheus surface; `docs/project-state.md` predates
   the Phase 3 reset and the 0.2.15/0.2.16 soaks (its own rule: rewrite,
   never append).

## Scope

- **Token:** remove `tui-monitor/config.toml` from tracking (gitignore it),
  ship a `config.example.toml` with placeholders. The owner rotates the API
  key after the removal lands (`POST /api/v1/auth/rotate` or documented
  equivalent) — rotation is the owner's action, listed in the review file
  as the closing step. Note: removal stops future exposure; the token stays
  in git history, which is why rotation is the real fix.
- **Layering guard:** derive the walk and the expected count from workspace
  members (tui-monitor included), match dependencies by `package =` target
  as well as key, and scan build- and target-specific dependency tables.
  The guard stays a plain test; no CI implied.
- **Docs (each edit requires the owner's explicit approval at execution
  time — this task lists, it does not pre-authorize):** reconcile
  `deploy-rb5009.md` §IPv6 with p2-14; purge `/metrics`/Prometheus
  references; rewrite `project-state.md` to the post-reset state. The
  `fah-metrics` crate-doc line is a Rust `//!` comment — touching it must
  satisfy the no-comments hook's existing-exception handling; if the hook
  rejects, record the drift in the review file instead.

## Acceptance criteria

- No tracked file contains a live credential; example config present;
  owner's rotation step recorded.
- Layering test fails on: a sibling edge in tui-monitor, a renamed internal
  dep, an internal dep in a build/target table (each demonstrated by a
  temporary negative test during development, not left in the tree).
- Approved doc edits applied; unapproved ones listed as pending in the
  review file.
- Gates green.

## Out of scope

API-key lifecycle changes; secrets management; CI; any Phase 3 doc.
