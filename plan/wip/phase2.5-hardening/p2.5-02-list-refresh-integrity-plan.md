# Plan — p2.5-02 List Refresh Integrity

## Summary

A fetched list body is parsed and gated **before** `commit_raw` can
overwrite the last-good `/data` copy; rejection is a first-class status
visible via the lists API, and `parse_errors` is exported per list. All
decisions below are final.

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Validation parser | `fah_rules::parse_rule_list(&text)` (`crates/fah-rules/src/lib.rs:30`) — the same entry compile uses; parsed form dropped after stats extraction |
| Gate rule 1 | `RefreshStats::looks_misparsed()` → reject |
| Gate rule 2 (collapse) | reject iff baseline exists AND baseline `active + url ≥ 1000` AND new `active + url < baseline (active + url) / 10` |
| Baseline source | the `compiled` field of the list's `ListStatus` (`lifecycle/mod.rs:162-177`) — survives restart via the compile from the cached copy; when `None`, the collapse check is skipped and only rule 1 guards |
| Constants | `COLLAPSE_MIN_BASELINE: usize = 1000`, `COLLAPSE_FACTOR: usize = 10`, both in `lifecycle/mod.rs` next to `MISPARSE_ERROR_FLOOR` |
| New status variant | `RefreshResult::Rejected(String)` (reason text: `"misparse: N errors, M rules"` or `"collapse: M rules vs baseline B"`) |
| New error variant | `LifecycleError::RejectedContent(String)` — returned by `fetch_and_commit`, recorded by both callers |
| Double-parse cost | accepted; measured once on the deployed corpus and recorded in the review file |
| API exposure | each entry in `ListsResponse` (`crates/fah-api/src/routes.rs:378-395`) gains `parse_errors: u32` (from `compiled` stats, 0 when `None`) and rejection surfaces through the existing last-result/error field as the `Rejected(reason)` rendering `"rejected: <reason>"` |

Correction over the earlier draft carried forward: baseline comes from
`ListStatus.compiled`, not from the last `Ok` refresh stats — `compiled`
is restored by the boot compile from the cached copy, which **removes the
first-refresh-per-boot blind window** the draft accepted. A list with no
cached copy (genuinely first fetch) has `compiled == None` and is guarded
by rule 1 alone — correct, since there is no last-good copy to protect.

## Implementation units

**U1 — gate in `fetch_and_commit`** (`lifecycle/mod.rs:637-654`). After
`fetch`, before taking `compile_lock`: `let parsed = parse_rule_list(&text);
let stats = RefreshStats::from(&parsed); drop(parsed);` then apply gate
rules 1-2 against `self.status(...).compiled`. On reject: return
`Err(LifecycleError::RejectedContent(reason))` — `/data` untouched,
`last_attempted` already recorded (unchanged), lock order unchanged
(`refresh_lock` held, `compile_lock` not yet taken).

**U2 — status plumbing.** Add the two variants; `refresh_list`
(:589-626) and `refresh_all` (:672+) record `RefreshResult::Rejected` on
`RejectedContent` (map the error at the `record_status` call sites — the
existing `Failed(error_chain)` path stays for every other error).
Exhaustive matches on `RefreshResult` surface every consumer; render
`Rejected` wherever `Failed` renders, prefixed `rejected:`.

**U3 — API.** `ListsResponse` entry: add `parse_errors: u32` populated
from `compiled.map(|s| s.parse_errors).unwrap_or(0)`; extend the
last-result serialization with the `Rejected` rendering. Additive only —
no renames, no removals. API.md delta proposed to the owner in the same
change; if approval is withheld, code ships and the doc edit is listed
pending in the review file.

## Invariants (must hold before and after)

- An I/O fetch failure behaves exactly as today (`Failed`, last-good
  kept, next attempt at the normal interval).
- A rejected body never reaches `/data` and never enters a compile.
- The served matcher is byte-identical across a rejected refresh.
- Lock ordering `refresh_lock` → `compile_lock` unchanged; the validation
  parse runs under `refresh_lock` only.
- Fetched text and parsed form are never both resident with another
  list's (serial fetch discipline, mod.rs:669-671, unchanged).

## Tests (all objectively checkable)

1. 200-OK HTML fixture (real error-page shape, > 100 lines) against a
   list with a seeded good cache → `Rejected`, reason starts `misparse:`,
   `/data` file byte-identical, matcher rule count unchanged.
2. Empty body against a seeded baseline of ≥ 1000 rules → `Rejected`,
   reason starts `collapse:`.
3. Body with baseline/10 − 1 rules → rejected; baseline/10 + 1 → accepted
   (boundary pinned).
4. No cached copy, garbage body under 100 parse errors → accepted
   (documents the rule-1-only guard for first fetches).
5. Legitimate small-delta update → commits, compiles, `Ok`.
6. Lists API response carries `parse_errors` and the `rejected:` text.
7. Existing I/O-failure tests unchanged and green.

## Out of scope (closed paths)

- No `pending_cache` aggregate bound; no Content-Length pre-check; no
  checksums/signatures; no retry-sooner-on-reject scheduling.
- No new endpoint, no query-log/Prometheus surface (p2-09 stands).
- No config keys for the gate constants.
- No change to `looks_misparsed`'s floor or formula.
