# Plan — p2.5-08 Hygiene: Token, Layering Guard, Stale Docs

## Summary

Three cleanups, executed in this order: untrack the live bearer token
(owner rotates after), rewrite the layering guard to cover the whole
workspace and its bypasses, reconcile three stale docs (each edit
owner-approved at execution).

## Decisions (all fixed)

| Decision | Value |
| --- | --- |
| Token handling | `git rm --cached tui-monitor/config.toml`; `.gitignore` gains the exact line `tui-monitor/config.toml`; new tracked `tui-monitor/config.example.toml` |
| Example config contents | every key the real file carries, placeholder values: FAH host/port/token (`host = "172.17.0.2"`, `port = 8443`, `token = "PASTE-API-KEY-HERE"`), the TLS-accept flag as currently shipped, RouterOS REST base URL + username/password placeholders |
| Rotation | owner's step, recorded in the review file: `POST /api/v1/config/apikey/rotate` (API.md:690) after the removal lands; RouterOS REST credentials rotated on the router by the owner; history retains the old token — rotation is the real fix |
| Guard rewrite | full rewrite of `crates/fastadhunter/tests/layering.rs`, comment-free (the hook rejects preserved `//!`/`///` in a Write; the file's documentation moves to the review file) |
| Member discovery | parse the workspace root `Cargo.toml` `[workspace] members` (`["crates/*", "tui-monitor"]`), expand `*` globs via `fs::read_dir`, require each expanded entry to have a `Cargo.toml`; `checked` asserts against the expanded count — the hardcoded 11 is deleted |
| tui-monitor rule | `fah-tui-monitor` gets an explicit allowlist: internal deps ⊆ `{fah-model}`; it is not placed in the L1-L4 ladder |
| Dep-name resolution | for each entry in every scanned table: real crate name = the `package` field when the value is a table containing one, else the key; the `fah-` filter and the layer assertion run on the real name |
| Tables scanned | `dependencies`, `dev-dependencies`, `build-dependencies`, plus every `target.<cfg>.{dependencies,dev-dependencies,build-dependencies}` |
| Negative-test protocol | each new detector (tui-monitor sibling edge, renamed dep, build-table dep, target-table dep) demonstrated once with a temporary violating manifest during development, then removed; the review file records each demonstration; the tree keeps only the green guard |
| Doc edits | three, each proposed as its own diff and applied only on explicit owner yes (below) |

## Implementation units

**U1 — token** (first, security): the three file operations above;
verify `git grep` of the token value over tracked files returns nothing
(record the command shape, never the token, in the review file); confirm
tui-monitor errors readably when `config.toml` is absent — if it panics,
fix to a one-line startup error naming the expected path and the example
file (that error-path fix is in scope; nothing else in tui-monitor is).

**U2 — guard rewrite** per the decisions table. Structure: helper
`members() -> Vec<PathBuf>`, helper `real_name(key, value) -> String`,
helper `internal_deps(manifest) -> Vec<String>` walking all tables, then
the assertion loop: `fah-tui-monitor` → allowlist check; crates in the
ladder → strictly-lower check; unknown crate → panic (unchanged
behavior); count assertion from `members()`.

**U3 — doc reconciliations** (each owner-gated, proposed in this order):

1. `docs/deploy-rb5009.md` §"IPv6 is not covered by the rules above"
   (~:695-706): replace the section body with the current state — v6
   dstnat mirror rules deployed and verified in p2-14
   (`docs/code-review/phase2/p2-14-review.md`); keep the section heading,
   point to p2-14 for the rules and evidence.
2. Prometheus/`/metrics` purge: `docs/routeros-traps.md:152` plus every
   hit of a repo-wide grep for `Prometheus|/metrics` in tracked `*.md`
   that describes a *current* surface (historical review files under
   `docs/code-review/` are records — leave them). The
   `crates/fah-metrics/src/lib.rs:1` `//!` line: **delete the line**
   (reword is hook-blocked); if the owner declines the deletion, record
   the drift in the review file.
3. `docs/project-state.md`: full rewrite (its own rule) to the post-reset
   state — Phase 2 closed, phase2.5-hardening in wip with this plan set,
   the reconciled review as gate, 0.2.17 current, Stage 1 → Phase 3
   sequencing. Content sources: the reconciled review + phase CLAUDE.md
   only; no new claims.

## Invariants (must hold before and after)

- The guard passes on the current tree unmodified (no latent violation
  exists — verified by running it before and after the rewrite).
- No tracked file contains a live credential after U1.
- `cargo test -p fastadhunter --test layering` remains the invocation.
- No workspace membership or dependency actually changes — the guard
  only widens what it sees.

## Tests

U2 is the test; plus: guard green on the tree, and each detector's
negative demonstration recorded. U1: the grep check; a tui-monitor start
without config yields the readable error.

## Out of scope (closed paths)

- No API-key lifecycle changes, no secrets tooling, no git-history
  rewrite/purge, no CI.
- No layering *policy* change — only enforcement coverage.
- No tui-monitor refactoring beyond the missing-config error path.
- No edits to ARCHITECTURE.md, SECURITY.md, or any Phase 3 document.
