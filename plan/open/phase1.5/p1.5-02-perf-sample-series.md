# P1.5-02 — Perf / System / Cache Sample Series

**Phase:** 1.5 · **Depends on:** p1.5-01 · **Model:** Opus

## Goal

A persisted, per-interval time-series of the *live* numbers a dashboard graphs
that aren't per-query aggregates: process **RSS/RAM**, QPS, verdict split,
**cache stats**, latency percentiles, and upstream health — the router
self-hosting what the soak curl-loop did externally.

## Context

Sources already exist; nothing here belongs on the hot path (root CLAUDE.md
hard rule #3). The binary already runs a telemetry-poll task that pushes
cache/upstream/ruleset snapshots into `Metrics`
(`crates/fah-metrics/src/registry.rs`) on a timer — this sampler is a sibling
task on the same cadence. Sources:

- **RSS:** `fah_metrics::process::resident_memory_bytes()`
  (`crates/fah-metrics/src/process.rs`).
- **QPS / verdict split / cache counts / latency:** `Metrics` — add a public
  `Metrics::snapshot()` returning a POD, plus percentile accessors on
  `crates/fah-metrics/src/histogram.rs` (p50/p99 estimated from the fixed
  buckets — document the resolution, don't imply exactness). QPS is derived
  from the delta between consecutive samples.
- **Cache stats:** the same snapshot behind `GET /api/v1/cache` (fah-dns cache
  admin port) — `entries/capacity/fresh/stale/expired/evictions/
  load_percent/hits/misses`.
- **Upstream health:** `fah_dns::upstream::UpstreamPool::status`
  (already polled into `Metrics`).

## Scope

- New POD `PerfSample` in **`fah-model`** (data + serde only):
  `{ ts, rss_bytes, qps, queries/blocked/allowed deltas, cache: CacheStats,
  latency: { block_p50, block_p99, cache_hit_p50, cache_hit_p99, forward_p50,
  forward_p99 }, upstreams: Vec<UpstreamSample> }`. Reuse the existing cache
  stats shape (lift its fields into a shared `fah-model` struct if it lives in
  fah-dns/fah-api today).
- `Metrics::snapshot()` + histogram percentile methods (public, read-only).
- New module `crates/fah-stats/src/history/perf.rs`: append `PerfSample` to
  `/data/history/perf/perf-YYYY-MM-DD.jsonl` (one file/day), reusing the
  SegmentWriter append+prune pattern; `prune(retention_days)`.
- Binary sampler task (`crates/fastadhunter/`): on `history.sample_interval`,
  gather RSS + `Metrics::snapshot()` + cache port + upstream status into a
  `PerfSample` and hand it (plain data) to `fah-stats` to persist. Siblings
  never import each other — the binary is the only place that touches all
  three (ARCHITECTURE.md §Dependency Layering).

## Acceptance criteria

- With the sampler running, a `perf-*.jsonl` accrues one row per interval with
  non-zero `rss_bytes` and populated cache stats + latency percentiles.
- QPS delta is correct across two samples.
- `prune` bounds disk by `retention_days`; sampler adds no unbounded memory.
- No new work on the per-query path (grep: sampler only reads snapshots).
- Gates green.

## Out of scope

The read API (p1.5-04); making `sample_interval`/`retention_days` REST-settable
(p1.5-03 — take them as config values here).
