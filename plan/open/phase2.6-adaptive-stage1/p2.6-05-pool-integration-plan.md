## Implementation changes

1. **`UpstreamPool`** gains `health: Arc<[Health]>`, `policy: Policy`,
   `epoch: Instant`, `strategy: UpstreamStrategy`. Built in `with_tls_config`:
   `Policy::from_timeout(config.timeout_ms, penalty_failures as u8)` (base =
   `10 × ATTEMPT_LEGS × timeout_ms`, C2), one `Health::new()` per server.
   Per C3 (decided): `attempts` and `failures` move into `Health`;
   `consecutive_failures` and `run_buckets` stay on `UpstreamServer`.
2. **`fallback` branch**: the existing loop body verbatim, with
   `server.attempts` / `server.failures` reading `self.health[index]`. No
   other edit. Behaviour identical; tests untouched.
3. **`adaptive` branch** — private `async fn forward_adaptive(&self, query, mode: HealthMode)`:
   ```text
   start = 0; last_err = None
   loop:
     cand = select(&health, start, || elapsed_ms(epoch))  — None → break
     if mode == Record: health[id].attempts += 1; if Probe: probes += 1
     result = servers[id].query(query, timeout).await
     if mode == Record:
        t = record(&health[id], classify(kind, &result), elapsed_ms(epoch), &policy)
        if let Some(run) = t.closed_run → run_buckets[run_bucket(run)] += 1
        if let Some(ms) = t.penalty_applied → penalties += 1; penalized_ms_total += ms
        if Probe && Ok → probe_successes += 1
     Ok → alarm.clear(); return ForwardOutcome(msg, id)
     Err → failures += 1 (Record only); last_err = Some; start = id + 1
   alarm.claim(); return last_err
   ```
   `elapsed_ms` is `Instant::now().duration_since(epoch).as_millis() as u64`,
   called at most twice per attempt and never on the all-Healthy success path
   (the closure in `select` is not invoked; `record(Success)` on a clean
   Healthy word needs no time — p2.6-02 M.5).
4. **`Forwarder::forward`** dispatches on `self.strategy`; the pipeline and
   SWR call it unchanged (`Record`). `lookup` calls
   `self.forward_with(query, HealthMode::Ignore)` under `adaptive`; under
   `fallback` it calls the existing path (no mode exists there).
5. **Path failure on a forced attempt**: handled inside `next_word`
   (Penalized + any failure = counter only) — no special case here.
6. **Alarm semantics** unchanged: `clear()` on any success, `claim()` when
   the scan exhausts. Under `adaptive` the scan exhausts after trying the
   Healthy set, at most one probe and the forced endpoint, so the alarm
   still fires during a full outage (S1.15).
7. **`status()`** keeps returning today's `UpstreamStatus` fields (new
   fields are p2.6-06); `consecutive_failures` reports the packed field
   under `adaptive`, the plain counter under `fallback`.
8. **Test seam for scaled policy**: `#[doc(hidden)] pub fn with_policy(config, policy) -> io::Result<Self>`
   (p2.6-09's bench is an external target and cannot reach `#[cfg(test)]`
   or `pub(crate)` seams). Default: `#[doc(hidden)] pub`; a `bench` feature
   only if the owner asks for one at task start.
9. Wrap no new `Arc`, `Vec`, `String` or `Box` on the forward path;
   `ForwardOutcome` stays as is.
