# P2.6-03 — Selection and Probe Claim

**Phase:** 2.6 · **Depends on:** p2.6-02 · **Model:** Opus

## Goal

Given `&[Health]`, `now` and a start index, the selector returns the next
endpoint to try in config order — first Healthy, else first Penalized whose
deadline passed (claimed as a probe by one CAS), else the earliest-deadline
endpoint with nothing claimed — and never returns "none" while endpoints
exist.

## Context

Spec S1.5 (selection algorithm, scan continues from the next endpoint on
failure), S1.7 (on-path probing, exactly one probe in flight per endpoint),
S1.3 hard invariant and its forced-use recording rule.

## Scope

- `select(&[Health], start, now_ms) -> Option<(EndpointId, Selected)>` where
  `Selected` is `Healthy | Probe | Forced`; `None` only for an empty slice.
- Probe claim: `compare_exchange_weak` Penalized → Probing on the packed word,
  preserving `penalty_round` and the deadline bits; a lost race continues the
  scan as if that endpoint were Penalized with a future deadline.
- Forced selection claims nothing and writes nothing.
- ≤ 8 relaxed loads, early exit on the first Healthy, no allocation.
- Continuation after a failed attempt: the caller passes `start = id + 1`;
  the function does not loop internally over attempts.

## Acceptance criteria

- S1-G1 #6 unit part: all Penalized, no deadline passed → earliest deadline
  returned as `Forced`; no `Probing` state anywhere; `probes` unchanged;
  after `record(hard failure)` on it, deadline and `penalty_round` unchanged.
- S1-G1 #8: N threads against one due endpoint → exactly one `Probe`, the
  rest `Forced` or the next Healthy.
- Boot: all Healthy → endpoint 0 on every call (S1.5 "bit-identical").
- Continuation skips Penalized endpoints and tries at most one probe per
  query.
- Gates green.

## Out of scope

Sending anything; `UpstreamPool` changes; RTT, scores, family preference.
