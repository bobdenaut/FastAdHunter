# P2.6-03 — Selection and Probe Claim

**Phase:** 2.6 · **Depends on:** p2.6-02 · **Model:** Opus

## Goal

Given `&[Health]`, a lazy clock, a start index and a `claim` flag, the
selector makes **one pass in config order** and returns the first endpoint it
can use: a Healthy one, or a Penalized one whose deadline has passed (claimed
as a probe by one CAS when `claim` is true, skipped when it is false); a
Penalized endpoint with a future deadline and a Probing endpoint are skipped.
If the pass selects nothing, the earliest-deadline endpoint is returned with
nothing claimed. It never returns "none" while endpoints exist.

## Context

Spec S1.5 (one-pass selection, lazy clock, `claim`, continuation from the
next endpoint on failure), S1.7 (on-path probing, exactly one probe in flight
per endpoint, lost CAS not retried), S1.8 (Ignore never claims — the
`claim = false` caller), S1.3 hard invariant and its forced-use recording
rule.

## Scope

- `select(&[Health], start, now: impl FnOnce() -> u64, claim: bool) -> Option<Candidate>`
  where `Candidate { id: u8, selected: Selected }`, `Selected` is
  `Healthy | Probe | Forced`; `None` only when `start >= len`.
- `claim` is a plain `bool`. `false` means a due endpoint is treated as not
  due (skipped, nothing stored). The caller (p2.6-05) passes
  `mode == Record && !probed`. **No dependency on `HealthMode`** — that type
  is p2.6-04's and is mapped to this bool at the call site.
- The clock closure is evaluated **at most once, at the first non-Healthy
  word**; a pass that meets a Healthy word first never evaluates it.
- Probe claim: `compare_exchange_weak` Penalized → Probing on the packed word,
  preserving `penalty_round`, `consecutive_failures` and the deadline bits; a
  lost race continues the pass as if that endpoint were Penalized with a
  future deadline — no retry.
- Forced selection claims nothing and writes nothing; the forced candidate is
  the smallest `timestamp_ms` among the Penalized **and Probing** words from
  `start`.
- ≤ 8 relaxed loads, no allocation, no store except the claim CAS.
- Continuation after a failed attempt: the caller passes `start = id + 1`;
  the function does not loop internally over attempts and does not know
  about the one-probe-per-query rule — the caller expresses it through
  `claim`.

## Acceptance criteria

- S1-G1 #6 unit part: all Penalized, no deadline passed → earliest deadline
  returned as `Forced`; no `Probing` state anywhere; `probes` unchanged;
  after `record(hard failure)` on it, deadline and `penalty_round` unchanged.
- S1-G1 #8: N threads against one due endpoint → exactly one `Probe`; with
  no other endpoint the rest are `Forced` on it, with a Healthy endpoint
  configured **behind** it the rest are `Healthy` on that id — and the due
  endpoint ahead of the Healthy one is still the one probed.
- S1-G1 #16 unit part: `claim = false` against `[due, Healthy]` → `Healthy`
  id 1, the due word byte-for-byte unchanged; `claim = false` against
  `[due]` → `Forced` id 0, word unchanged.
- Boot: all Healthy → endpoint 0 on every call, clock never evaluated (S1.5
  "bit-identical").
- Continuation skips Penalized-not-due and Probing endpoints.
- Gates green.

## Out of scope

Sending anything; `UpstreamPool` changes; RTT, scores, family preference.
