# P2.6-10 — Null A/B, Suite S1-N

**Phase:** 2.6 · **Depends on:** — · **Model:** Opus

## Goal

The live harness's noise band **N** is measured from a null A/B — one binary,
two labels, K ≥ 6 alternating repetitions — so S1-G2 tier 3 carries a derived
threshold (`max(2 × N, 5 %)`) or is dropped (N > ~10 %), instead of a number
nobody can defend.

## Context

Spec S1-G2 (why ±2 % was withdrawn; dimensions to validate; freezing rule),
open measurement 6 ("runs before S1-L"). Control-arm drift recorded in
docs/measurement-traps.md §Carry a control arm (+8.8 %, −4.6 %). Benchmark
plan: docs/design/adaptive-upstream-selection-benchmarks.md §S1-N.

## Scope

- Runs against the `fallback` binary — no Stage 1 code needed, so this task
  can run whenever the probe container is available.
- Metrics per repetition: `forward` p99, `cache_hit` p99 (control arm), total
  upstream attempts, attempts per forward, SWR attempts.
- Report N per metric, control-arm drift, and the resolution-vs-K curve.
- Decide and record: which metric carries tier 3, whether SWR needs its own
  arm, and whether the live timing gate survives.
- Router side is read-only or owner-run: **propose every command, never
  execute it** (working agreement).
- Results file: `docs/code-review/phase2.6/p2.6-10-null-ab-review.md`.

## Acceptance criteria

- K ≥ 6 alternating repetitions completed; N stated per metric with the
  session, device and workload.
- If `cache_hit` moved more than `forward`, the session is void and says so.
- S1-G2 tier 3 either frozen at `max(2 × N, 5 %)` on the named metric or
  dropped, with the reason.

## Out of scope

Running the adaptive binary; any change to code.
