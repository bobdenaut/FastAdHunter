# P2.6-08 — Microbench S1-M (G2 tier 1)

**Phase:** 2.6 · **Depends on:** p2.6-05 · **Model:** Opus

## Goal

"Not slower than `fallback` on a healthy link" is decided here, at
nanosecond resolution, pinned and single-core: the healthy-path selection
under `adaptive` is one relaxed load with early exit and zero allocations.

## Context

Spec S1.11 (hot-path table), S1-G2 tier 1 (precision at the microbench — the
live timing gate cannot resolve this), docs/measurement-traps.md and
PERFORMANCE.md §Measuring reliably (pinning recipe, A/B against a real
pre-change checkout, never criterion's stored baseline). Benchmark plan:
docs/design/adaptive-upstream-selection-benchmarks.md §S1-M.

## Scope

- Criterion bench: `select` over 1, 2, 4, 8 endpoints, all Healthy; and the
  `forward` stage against a loopback mock under both strategies.
- Allocation count on the forward path: 0 added, asserted with the existing
  counting allocator pattern.
- A/B: build the pre-`p2.6-05` checkout, run the same bench, same pin, same
  session; report both with the CI.
- Results file: `docs/code-review/phase2.6/p2.6-08-microbench-review.md`
  carries corpus, workload, device, pin, CI.

## Acceptance criteria

- `adaptive` healthy-path `select` ≤ `fallback` equivalent within the bench
  CI (< 1 % by the project's pinned recipe); any regression > 10 % on
  `forward` stage is a blocker per root CLAUDE.md.
- 0 allocations added on forward, cache hit and block stages.
- Gates green; `cargo bench` compiles.

## Out of scope

Live-run timing (tier 3, `p2.6-10`/`p2.6-11`); injected failures (`p2.6-09`).
