## Implementation changes

1. **Harness** `crates/fah-dns/tests/support/mock_upstream.rs`: one
   `MockUpstream` with the six knobs; `script` as timed phases
   (`Phase { for: Duration, behaviour }`); binds `127.0.0.1:0` / `[::1]:0`.
   Shared by tests and by the bench target via
   `#[path = "../tests/support/mock_upstream.rs"]`.
2. **Suite** `crates/fah-dns/tests/adaptive_behaviour.rs`, `#[ignore]`-free
   but time-scaled: `timeout_ms` scaled down (e.g. 50 ms) and `Policy`
   scaled in proportion so B.5's minutes become seconds; the ratio
   `penalty_base / timeout` is kept at 10 and `penalty_max / penalty_base`
   at the shipped ratio, so the shape is the shipped shape.
   Arms B.1–B.8 per the doc, each run under both strategies in the same
   test body, `penalty_failures` swept {1, 2, 3} for B.1/B.2.
3. **Metrics collected per arm**: client p50/p99 and first-10 latencies;
   count of queries whose latency ≥ the per-leg `timeout_ms` ("paying"
   queries) and the **measured** time each paid; time-to-penalize (queries,
   wall clock); `status()` over time; B.4 "no packet sent" count
   (harness-side: the mock counts received datagrams; the assertion is
   `forwards == datagrams_seen` across both mocks); B.8 probe attribution
   **harness-side** — C7 below.
4. **Net timeout cost avoided** (spec §S1-G3): from the counts,
   `net_avoided = (fallback_paying − adaptive_paying) × attempt_bound_ms − failed_probes × attempt_bound_ms`
   with `attempt_bound_ms = ATTEMPT_LEGS × timeout_ms` as the cap, and the
   same formula over the **measured** paid time beside it. The plain-UDP
   mocks never truncate, so measured ≈ one leg (`timeout_ms`); state that
   the bound is the worst case. Computed twice: once over client `forward`s
   (B.1/B.2/B.5), once over SWR refreshes (B.8). The cache-hit-adjusted
   line uses the deployed composition from the spec (§Upstream traffic
   composition: 10 % client forwards, 69 % SWR) to state what fraction of
   client queries the figure touches.
5. **Results file** `docs/code-review/phase2.6/p2.6-09-injected-failure-bench-review.md`
   with the doc's acceptance table filled in per arm and strategy.

## Tests

The suite is the test. Acceptance per arm (benchmarks doc):

- B.1 `adaptive`: ≤ `penalty_failures` queries pay (each at most
  `attempt_bound_ms`; one leg on these mocks); remainder at ~mock latency.
  B.1 `fallback`: every query pays — the tax being removed.
- B.2: ≤ 1 query pays anything.
- B.3: arms within noise; `penalties == 0`.
- B.4: zero queries with no packet sent; both endpoints probed at their
  deadlines.
- B.5: Healthy within `penalty_max` + one query interval; never > 1 probe
  in flight; flapping shows growing `penalty_round` and no probe storm;
  `penalty_round` does **not** reset during the healthy phase shorter than
  `penalty_max`.
- B.6: `state` and the packed word unchanged; only `attempts` moves.
- B.7: nothing moves, `attempts` included.
- B.8: SWR-claimed probes > 0; dropped jobs bounded; no unbounded retry.
