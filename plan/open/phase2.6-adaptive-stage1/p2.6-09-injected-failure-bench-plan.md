## Implementation changes

1. **Harness** `crates/fah-dns/tests/support/mock_upstream.rs`: one
   `MockUpstream` with the five knobs; `script` as timed phases
   (`Phase { for: Duration, behaviour }`); binds `127.0.0.1:0` / `[::1]:0`.
   `refuse` binds, records the port and drops the socket. The DoT
   refused-endpoint arm needs no TLS mock: a dropped `TcpListener`'s address
   in a `dot` entry built with `UpstreamPool::from_config` refuses before any
   handshake. Shared by tests and by the bench target via
   `#[path = "../tests/support/mock_upstream.rs"]`.
2. **Suite** `crates/fah-dns/tests/adaptive_behaviour.rs`, `#[ignore]`-free
   but time-scaled: `timeout_ms` scaled down (e.g. 50 ms) and `Policy`
   scaled in proportion so B.5's minutes become seconds; the ratio
   `penalty_base / timeout` is kept at 10 and `penalty_max / penalty_base`
   at the shipped ratio, so the shape is the shipped shape.
   Arms B.1–B.8 per the doc, each run under both strategies in the same
   test body, `penalty_failures` swept {1, 2, 3} for B.1/B.2.
   B.1 issues its 10 000 queries **sequentially** — the "≤ `penalty_failures`
   pay" count is only meaningful for queries dispatched after the penalty
   landed (M7). B.2 has two arms: UDP closed port under
   `#[cfg(target_os = "linux")]` (Windows reports `ConnectionReset`, a hard
   failure — spec S1.4 platform note), and a DoT endpoint on a closed TCP
   port that runs everywhere (M6). B.4 runs its queries sequentially too, so
   every forced attempt lands on a Penalized word (H3); the concurrent
   forced-on-Probing case is covered by the S1.3 rule, not asserted here.
   B.5 keeps B healthy throughout — the probe on A must be claimed although
   B is Healthy (B1) — runs **sequential queries at 20 QPS scaled** (one
   query interval = 50 ms, the unit in the recovery criterion), and ends
   with the **healthy 1.2 P → black hole 0.1 P tail**, the only phase where
   a ≥ P healthy stretch precedes a penalty, so the round reset is observed
   (`penalty_round == 1` at that last penalty), not just unit-tested. The
   mock records its high-water mark of concurrently outstanding requests
   (the in-flight-probe measurement; ≤ 1 is trivial under sequential issue
   and the concurrent claim rests on G1 #8). B.3 is decided on counts; its
   latencies are reported. B.6 is the end-to-end owner of G1 #5's state
   half (`state` and `consecutive_failures` unchanged under `adaptive`
   across NXDOMAIN/SERVFAIL/REFUSED). B.7 adds a second pass with A
   pre-penalized and due. B.8's client-only pass uses distinct never-cached
   names so no stale hit ever enqueues a refresh; both passes record the
   number of distinct stale keys created, `swr.enqueued`, `swr.dropped`,
   `swr.failed`.
3. **Metrics collected per arm**: client p50/p99 and first-10 latencies;
   count of queries whose latency ≥ the per-leg `timeout_ms` ("paying"
   queries), **split into non-probe and probe-carrying by the `probes` delta
   around each sequential query**, and the **measured** time each paid;
   time-to-penalize (queries, wall clock); `status()` over time; B.4 "no
   packet sent" count (harness-side: the mock counts received datagrams; the
   assertion is `forwards == datagrams_seen` across both mocks); B.8 probe
   attribution **harness-side** — C7 below.
4. **Net timeout cost avoided** (spec §S1-G3): from the counts,

   ```text
   adaptive_paying = non-probe paying queries      (probe carriers excluded)
   probe_cost      = failed_probes × attempt_bound_ms
   net_avoided     = (fallback_paying − adaptive_paying) × attempt_bound_ms − probe_cost
   ```

   with `attempt_bound_ms = ATTEMPT_LEGS × timeout_ms` as the cap, and the
   same formula over the **measured** paid time beside it. `adaptive_paying`
   excludes the probe carriers — they are `failed_probes`, and counting them
   in both terms subtracts each twice (validation H-B1). The plain-UDP mocks
   never truncate, so measured ≈ one leg (`timeout_ms`); state that the
   bound is the worst case. Computed twice: once over client `forward`s
   (B.1 and B.5 — B.2 contributes nothing, a refusal is ~free under
   `fallback` too), once over SWR refreshes (B.8). The cache-hit-adjusted
   line uses the deployed composition from the spec (§Upstream traffic
   composition: 10 % client forwards, 69 % SWR) to state what fraction of
   client queries the figure touches. The **tax-free share** (queries paying
   nothing ÷ queries after the penalty landed) is reported **per
   `PENALTY_MAX / PENALTY_BASE` ratio** — the run spans ~6 windows at 12.5
   and ~13 at 2.5, so one percentage would be wrong for at least one of them
   (validation H-B2).
5. **Results file** `docs/code-review/phase2.6/p2.6-09-injected-failure-bench-review.md`
   with the doc's acceptance table filled in per arm and strategy.

## Tests

The suite is the test. Acceptance per arm (benchmarks doc):

- B.1 `adaptive`: ≤ `penalty_failures` **non-probe** sequential queries pay
  (each at most `attempt_bound_ms`; one leg on these mocks); thereafter only
  probe carriers pay, one per window, counted as `failed_probes`; remainder
  at ~mock latency; tax-free share per ratio. B.1 `fallback`: every query
  pays — the tax being removed.
- B.2: the endpoint is Penalized after one attempt for every
  `penalty_failures` in the sweep and ≤ 1 query pays anything (UDP arm on
  Linux; DoT arm everywhere). Classification only; not a net-cost input.
- B.3: `penalties == 0`, `attempts` equal between arms, `state` Healthy
  throughout; latencies reported, not gated.
- B.4: zero queries with no packet sent; a forced failure on a Penalized
  word leaves deadline and round unchanged; both endpoints probed at their
  deadlines.
- B.5: Healthy within `penalty_max` + 50 ms of the "healthy 0.6 P" phase
  start, B Healthy throughout; mock outstanding-request high-water mark at A
  while Penalized/Probing ≤ 1; flapping phase: `penalty_round` strictly
  increasing across consecutive penalties until the cap, `probes` delta ≤
  penalty windows elapsed in the phase, `p99_flapping ≤ 1.1 × p99_black_hole`;
  `penalty_round` does **not** reset during the 0.6 P healthy phase and
  **does** reset after the 1.2 P tail — the final 0.1 P black hole penalizes
  at `penalty_round == 1`.
- B.6: `state` and the packed word unchanged; only `attempts` moves (G1 #5
  state half).
- B.7: nothing moves, `attempts` included; second pass: the due word
  unchanged, `probes == 0`.
- B.8: SWR-claimed probes > 0 (with the second endpoint Healthy — the
  one-pass selector claims ahead of it); `swr.dropped` reported;
  `swr.enqueued ≤ stale_keys × ceil(pass_duration / REFRESH_FAILURE_COOLDOWN)`.

## Contradictions — resolved by the owner (2026-08-23)

- **C7 — B.8 probe attribution: harness-side, no telemetry state.** Run
  B.8 twice: with **no client queries** (every probe counted is SWR's) and
  with client queries only. The benchmarks doc's B.8 metric line is read as
  this two-pass measurement; no `.md` edit needed.
- **C2 — attempt length.** Spec S1.6 defines `attempt_bound_ms`; step 4
  uses it as the cap and reports measured paid time beside it. These mocks
  never truncate, so one attempt = one leg here; state that scope in the
  results file.
- **Scaled constants.** Benchmarks doc §S1-B now states B.5 in units of
  `PENALTY_MAX` and sweeps the `PENALTY_MAX / PENALTY_BASE` ratio
  {2.5, 12.5, 37.5}; the configuration section states the scaling rule.
  Any case for a different `PENALTY_MAX` is a spec amendment for the owner,
  confirmed on-device in S1-L L.4a.
- **M6 / M7 / H3 / B1 / B2 (validation 2026-08-23, accepted):** B.2 split
  by platform, B.1 and B.4 sequential, B.4's invariance asserted on the
  Penalized row, B.5 with B Healthy throughout, B.7 second pass for the
  Ignore-never-claims rule. The task file's earlier `timeout_ms` wording
  in the net-cost formula is corrected to `attempt_bound_ms` (H2).
- **Scaled `timeout_ms` vs validation.** The harness scales `timeout_ms`
  down (e.g. 50 ms); p2.6-01's `1..=10_000` range still admits it. The
  `Policy` is injected through `with_policy`, not derived from the config,
  so the scaled base/max ratios are free.
- **H-B1 / H-B2 / M-B1–M-B4 / LOW (benchmark validation 2026-08-23,
  accepted):** `adaptive_paying` excludes probe carriers (step 4); "≤
  `penalty_failures` pay" restated as non-probe queries with probe carriers
  reported separately and the tax-free share per ratio (step 4, §Tests);
  no `unreachable` knob (step 1); B.3 count-based; B.5 healthy tail for the
  round reset; B.2 excluded from net cost; B.8 passes defined and driven
  through `Pipeline::spawn_swr_workers`. B.5's run length grows by 1.3 P per
  ratio — at 37.5 (P ≈ 56 s scaled) that is ~73 s more, so B.5 is
  `#[ignore]` and run explicitly, per §Benchmarks / gates.
