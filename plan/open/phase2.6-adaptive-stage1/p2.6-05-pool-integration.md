# P2.6-05 — Pool Integration

**Phase:** 2.6 · **Depends on:** p2.6-01, p2.6-02, p2.6-03, p2.6-04 · **Model:** Opus

## Goal

`UpstreamPool::forward` runs Stage 1 when `strategy = "adaptive"`: select,
attempt, record, continue the scan skipping Penalized endpoints. `resolve_host`
runs in `Ignore`. SWR workers inherit the behaviour through `Forwarder`. The
`fallback` path is untouched and every existing upstream test passes
unmodified.

## Context

Spec S1.2 (hot/cold split: `Arc<[Health]>` and the cold endpoint array),
S1.5, S1.7, S1.8 (`resolve_host` is ~20 % of attempts — isolation is
load-bearing), S1.9 (SWR is ~69 % — it records health and claims probes),
S1.11 (zero allocations, no locks, no timers), S1.14 (`fallback` is not
re-expressed as adaptive-with-penalties-off), S1.15 scenarios, S1.16
checklist, S1.17 (skip before connect; single-flight handshake kept).

## Scope

- Build `Policy` from config at pool construction (`penalty_base = 10 ×
  timeout_ms`, `penalty_max = 300 s`, `penalty_failures` from config).
- Split `UpstreamServer` counters into the `Health` array; cold data stays
  where it is. `EndpointId` = config index.
- `forward` under `adaptive`: loop `select → attempt → classify → record`,
  `start = id + 1` on failure, at most one probe per query. `Instant::now()`
  read once per attempt where the clock is already needed.
- `resolve_host` → `lookup` passes `HealthMode::Ignore`; selection still
  skips Penalized endpoints.
- `fallback` branch: the existing code, byte-for-byte where possible.
- The `ExchangeConn` slot lock stays; penalizing never closes a connection.

## Acceptance criteria

- S1-G1 #4: every existing upstream test unmodified and green under
  `fallback`.
- S1-G1 #6 integration: all endpoints Penalized → a packet is still sent.
- S1-G1 #7: `resolve_host` with one family black-holed moves no counter and
  no state.
- S1-G1 #8 integration: concurrent `forward` calls against a due endpoint →
  exactly one `Probing` claim, `tls_handshakes` of the dead endpoint
  unchanged after penalization.
- S1.17 tests: N concurrent queries against `[penalized-dead, live]` all
  answer within one `timeout_ms` of the live endpoint; N concurrent first
  queries against one live encrypted endpoint → exactly one handshake.
- Forward path adds no allocation (assert with the existing allocation
  counting pattern from the benches, or `#[global_allocator]` test hook).
- `tests/layering.rs` unchanged and green. Gates green.

## Out of scope

Telemetry fields (`p2.6-06`); benches (`p2.6-08`, `p2.6-09`); deleting
`fallback` (`p2.6-12`).
